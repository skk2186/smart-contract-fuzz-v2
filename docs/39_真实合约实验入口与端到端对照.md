# 39 真实合约实验入口与端到端对照

## 结论摘要

Phase39 建成并实测了通用 Echidna / Anvil 执行入口，Drips 的原生 assertion Harness 完成编译和 Echidna 最小运行。Drips 构造部署在 Anvil 上回滚，且 Harness 依赖 `hevm.prank` / `hevm.warp`，账户和时间语义不能在同一 Anvil 环境中保持等价。Drips 此前参与方法与工程调试，只能作为回归样本。

其余三个候选的固定 commit 已在 Phase29 按相同版本审查过：Liquity pinned submodule 获取两次失败，Superform 的固定源码获取两次未成功，Aave 缺少 pinned Harness 依赖且编译未通过。依照本轮“不重复已证明无效的工程路径”要求，没有重跑这些获取流程。冻结候选用尽后，没有项目通过原生属性运行与 Anvil 等价回放两道门槛，未启动正式 G0/E1/G1/G2。

结论为 **B：当前入口能够运行，独立项目收益尚无配对数据，需要先解决 Harness 语义和可复现依赖获取问题**。本报告没有把接入 smoke、静态属性线索或未运行的组别记为方法收益。

## 研究问题与下一步门槛

1. 真实项目是否完成端到端 G0/E1/G1/G2？**没有。** Drips 的 native G0 smoke 可运行，Anvil 构造失败；其余项目由既有固定版本依赖/源码获取障碍挡在编译前。
2. G2 是否有相对 G1 的独立收益？**无可归因数据。** G1/G2 没有运行。
3. 当前最大障碍是什么？**Harness 需要保留的 cheatcode 语义无法在普通 Anvil 回放中对齐，加上其他候选的 pinned 依赖/源码快照无法复现。**
4. 可以直接扩大正式论文实验规模吗？**暂不可以。** 需要先取得一个不依赖不可等价 cheatcode 且依赖完整的固定项目，在不改属性和业务逻辑的条件下通过 compile、native Echidna、Anvil 部署/状态读取/交易回放；随后冻结任务并再跑 G0/E1/G1/G2。Phase39 候选已用尽，不在本阶段追加目标。

结论选项 **B**。原始冻结、修复、运行日志、spec、摘要和候选筛选记录均保存在 [Phase39-20261121 结果目录](../func/测试过程/SCFuzzBench公开项目接入/结果/Phase39-20261121/)。

## 论文结构草案

以下提纲按当前实现和证据组织，不预填文献和实验结果。

1. **引言**：说明显式安全属性中的跨交易状态依赖问题，明确研究问题和适用边界。
2. **背景与相关工作**：属性测试、交易序列生成、状态依赖分析、运行时反馈和种子引导 fuzzing；引用待正式检索与核验。
3. **问题定义**：属性、相关状态、前置交易、目标状态、完整可执行序列、属性反例及 fuzz 新增覆盖。
4. **方法**：显式属性状态依赖分析与 Agent A/B 初始交易规划；属性状态反馈下的有界自适应序列扩展；跨交易前置约束绑定与参数修复；基于 Anvil 回放和独立 getter / trace 的候选验证。
5. **实现**：静态分析、交易建模、执行反馈、Echidna seed-only / fuzz 测量和可复现执行入口。
6. **实验设计**：冻结真实项目、commit、属性任务和目标状态；比较原生基线、Agent 原始种子、关闭绑定和开启绑定组；报告候选成本、完整交易成功、目标状态到达、反例、seed-only 回放与 fuzz 新增覆盖。
7. **实验结果**：分别报告开发集、工程接入、独立项目和消融。Phase37 3/3 仅为开发集证据；Phase39 记录 Drips G0 接入 smoke 与 Anvil 部署不兼容，不能作为 G2 收益。
8. **威胁与局限**：项目和属性代表性、Harness / cheatcode 语义、工具与预算差异、覆盖度量、种子已有覆盖和统计功效。
9. **结论**：以正式配对实验回答研究问题；未运行组别留空，不作性能判断。
