## 属性与冻结方案

参考 OWASP Smart Contract Security Testing Guide 的业务逻辑与经济安全指导，以及 OWASP SC02:2026 对跨操作记账不一致、路径依赖状态与不变量违例的讨论：[SCSVS-GOV 指南](https://scs.owasp.org/SCSTG/tests/SCSVS-GOV/overview/)、[SC02:2026](https://scs.owasp.org/sctop10/SC02-BusinessLogicVulnerabilities/)。这些材料给出安全目标和风险类别，不规定本样本的下列属性；本阶段将其具体化为可执行测试不变量，并在查看任何 Phase30A V2 结果前冻结。

属性为：测试账户通过 withdraw / refund 累计收到的 ETH，不得超过通过 deposit 累计存入的 ETH。Harness 以自身作为 Wallet 的唯一记账账户；只在成功存款后增加存款计数，只按成功调用后的实际余额增量记录提款。初始属性为真，目标状态为累计提款超过累计存款。属性适用于 Harness 暴露的存款、提款和退款操作；owner-only 迁移操作以及绕过 Harness 的强制转账不在此账本范围内。该 Harness 未修改 Wallet 业务代码。

属性语义、适用条件、局限、Agent 预算、Echidna 预算、账户和比较门槛已冻结在 [01-input-freeze.json](../func/测试过程/SCFuzzBench公开项目接入/结果/Wallet02Refund/01-input-freeze.json)。环境阻塞证据在 [02-execution-environment.json](../func/测试过程/SCFuzzBench公开项目接入/结果/Wallet02Refund/02-execution-environment.json)。
