# 22 公开论文基准复现与实验接入

## 阶段结论

已从 Olympia 官方生成器固定种子构建 12 个 Solidity 样本，并在运行原生 Echidna 基线前登记了 8 个开发样本和 4 个独立留出测试样本。数据来源是**本仓库按固定种子新生成的小型基准**，不是论文实验所用的原始 200 个合约。论文原始合约和 seed 清单在核对的官方仓库提交中未找到。

原生 Echidna 2.2.3 在 12 个样本中发现目标 2 个（16.7%）：开发集 2/8，留出集 0/4。留出集结果只用于本次独立评估，没有作为模型输入或用于调参。本轮预算为每样本 60 秒，属于框架试跑，不等同论文每合约 60 分钟的完整实验。

当前 V2 与 Olympia 在任务概念上相近：目标是按顺序调用状态化入口 `step(int8[])`，直到属性被违反。但 V2 的 Agent B 不支持 `int8[]` 参数编码，属性上下文也没有任意源码入口，因此无法直接对同一合约生成可回放交易序列。本阶段没有修改 Agent A/B 核心算法，也没有针对基准合约编写绕过逻辑。

## 论文与官方实现核实

[Olympia 论文](https://mariachris.github.io/Pubs/ASE-2024-Olympia.pdf)描述的是合成迷宫合约：`step(int8[] calldata)` 每笔交易推进一个状态，模糊测试器通过交易序列探索状态，bug 标志由 Echidna 属性检查。论文实验有 4 种迷宫尺寸（5×5、10×10、15×15、20×20），每种 50 个，共 200 个合约；其余生成参数随机选择，比较 Foundry、Medusa、Echidna 和 ItyFuzz，预算为每合约 60 分钟。

核对的 [Olympia 官方仓库](https://github.com/Rigorous-Software-Engineering/olympia/tree/325b910388416750d3485c7b588aba4411971c2d)固定在提交 `325b910388416750d3485c7b588aba4411971c2d`。该提交提供生成器、复现脚本和各模糊测试器的 Docker 配置；未找到论文中的 200 个已生成 Solidity 合约或其完整原始 seed 清单。因此本报告不把本地生成样本称为论文原始数据，也不声称复现了论文的 200 合约结果。

[官方 Echidna Dockerfile](https://github.com/Rigorous-Software-Engineering/olympia/blob/325b910388416750d3485c7b588aba4411971c2d/dockers/echidna/Dockerfile)固定 Echidna 2.2.3，并安装 `crytic-compile`、Slither 和 `solc-select`；[官方 Echidna runner](https://github.com/Rigorous-Software-Engineering/olympia/blob/325b910388416750d3485c7b588aba4411971c2d/dockers/echidna/run_echidna.sh)使用 solc 0.8.26、属性模式、`testLimit=1073741823`、`seqLen=100`、`shrinkLimit=5000`、覆盖率、失败后停止、`codeSize=0xc00000` 和优化参数 `--evm-version paris --optimize --optimize-runs 99999`。本实验沿用这些值，把 fuzzing `timeout` 从 60 分钟缩为 60 秒，并将 Echidna 官方默认单 worker 明确设为 1；每样本只运行一次。

官方 README 的完整批量流程是用 `scripts/run_tools.py` 读取 `programs.list` 和配置文件、启动 Docker 中的模糊测试器，再用 `scripts/save_results.py` 汇总报告；README 示例配置可指定多个 seed 和重复运行。本轮核实了该流程与容器配置，但为便于保存逐样本配置、Echidna 覆盖产物和资源计量，使用固定版本的 Echidna 原生二进制逐样本执行相同官方 runner 配置，没有声称跑过官方 Docker 编排的完整 200 合约流程。

论文图示的属性名为 `echidna_no_bug`；核对的官方生成器实际生成 `echidna_noBug()`。实验使用官方源码生成的真实属性名，属性语义仍是 bug 标志为 false。

## 数据集与预登记切分

Olympia wrapper 固定全局种子 `20261116`，每个维度生成 3 个样本，共 12 个；使用官方算法选项 `Backtracking`、`Kruskal`、`Prims`、`Wilsons`、`Sidewinder`，生成方法 `default`、`equality`，等式比例 25/50%，cycle 比例 0/25/50/75/100%。wrapper 为每个样本派生的实例种子、迷宫种子、算法和生成参数均保存在样本的 `生成参数.json`、`programs.list` 和生成方案中。CVE 约束生成方法没有纳入本轮。

每个尺寸的 wrapper 输出前两个样本划入开发集，第三个样本划入留出测试集，切分在任何 Echidna campaign 开始前写入 `实验方案.json`。因此开发集 8 个、留出集 4 个，每种尺寸在留出集中各有 1 个。源码按原样复制并记录 SHA-256；样本目录位于：

- `sol/单合约测试/OlympiaASE2024/development/<sample>/`
- `sol/单合约测试/OlympiaASE2024/heldout/<sample>/`

官方生成器的 reachability 预检查使用 `--disable-reachability-check` 关闭。当前 wrapper 即使该选项开启，仍会导入预检查模块；驱动脚本用一个“若被调用即报错”的临时占位模块处理该可选导入，确保关闭的检查不会暗中运行或改变生成过程。生成源码随后由固定 solc 和 Echidna 2.2.3 独立编译、部署和执行。官方输出中的 `sol_tx/`、`sln/`、迷宫文本/图片和 Foundry 包装器没有归档到样本，也没有交给 Agent；成功归档后，`.tools/` 下的生成暂存目录已清除。Agent 未被调用，DeepSeek API 未调用。Echidna campaign 自身产生的日志、覆盖报告和语料留在原生基线结果目录，它们是基线输出，不是提供给 Agent 的输入。

## V2 接入检查

[V2 检查结果](../func/测试过程/Olympia公开基准/结果/ASE2024-20261116/v2-compatibility.json)来自原生 Echidna 基线完成后的离线静态检查：

- 12/12 样本都暴露 `step(int8[])`，属性均为 `echidna_noBug()`。
- Agent B 能规范化标量 `int8`，但 `normalize_argument("int8[]", [-1])` 抛出 `ValueError: 暂不支持原生语料编码类型：int8[]`。
- V2 属性上下文的 `PROJECTS` 注册表目前只有 BeeStorage、Drips、Hokusai、Immutable、Kink、OpenNFTs 和 Request，没有 Olympia 任意生成源码的入口。
- 检查没有调用 API，没有读取基准生成的解答，也没有修改 Agent 核心逻辑。

因此当前版本不能给这 12 个源文件生成与原生 Echidna 同属性、同运行环境、同测试预算的 V2 配对 campaign。本报告将其记为“无法直接接入”，不以替换动态数组或按基准名注册的办法制造假对照。若后续决定扩展通用 ABI 编码和任意合约上下文，应只在开发集做通用功能开发，再用 4 个留出样本评估。

## 复现步骤与产物

下列命令在 Linux/WSL shell 中执行；官方仓库和工具只放在忽略的 `.tools/`。需要使用 Python 3.11。二进制下载后应校验版本和 SHA-256；本轮 Echidna 官方发布页为 [v2.2.3](https://github.com/crytic/echidna/releases/tag/v2.2.3)。

```bash
git clone https://github.com/Rigorous-Software-Engineering/olympia .tools/olympia-upstream
git -C .tools/olympia-upstream checkout 325b910388416750d3485c7b588aba4411971c2d

python3.11 -m venv .tools/olympia-venv
.tools/olympia-venv/bin/pip install \
  numpy==1.23.4 matplotlib==3.9.0 mazelib==0.9.14 \
  crytic-compile==0.4.2 slither-analyzer==0.11.6

mkdir -p .tools/olympia-echidna .tools/olympia-solc
curl -L https://github.com/crytic/echidna/releases/download/v2.2.3/echidna-2.2.3-x86_64-linux.tar.gz \
  -o .tools/olympia-echidna/echidna-2.2.3-x86_64-linux.tar.gz
tar -xf .tools/olympia-echidna/echidna-2.2.3-x86_64-linux.tar.gz \
  -C .tools/olympia-echidna
curl -L 'https://binaries.soliditylang.org/linux-amd64/solc-linux-amd64-v0.8.26+commit.8a97fa7a' \
  -o .tools/olympia-solc/solc-v0.8.26
chmod +x .tools/olympia-solc/solc-v0.8.26

.tools/olympia-venv/bin/python 'func/测试过程/Olympia公开基准/生成Olympia基准.py'
.tools/olympia-venv/bin/python 'func/测试过程/Olympia公开基准/运行原生Echidna基线.py' \
  --echidna .tools/olympia-echidna/echidna
.tools/olympia-venv/bin/python 'func/测试过程/Olympia公开基准/检查V2接入.py'
```

生成脚本会校验 Olympia 提交、拒绝覆盖已有数据集/结果目录、保存官方参数和源文件哈希，并在归档后清除 `.tools/` 暂存输出。重复实验请使用新的 `--dataset-dir`、`--results-dir`、`--generator-output` 和 `--work-dir`；基线重复时另用新的 `--run-id`。若只需从已有原始日志重建统计，可运行：

```bash
.tools/olympia-venv/bin/python 'func/测试过程/Olympia公开基准/运行原生Echidna基线.py' \
  --rebuild-summary-from-logs --run-id native-echidna-60s
```

## 本阶段限制

本轮样本为 12 个、单次重复、60 秒 fuzzing 预算；论文是 200 个样本、每个 60 分钟。机器也不同，因此结果只用于验证公开生成器、固定输入、基线执行和数据采集链路，不用于重新排名论文中的模糊测试器或评估 V2 算法优劣。V2 的同预算对照因通用接入能力不足未执行。论文原始 200 个合约的缺失状态以本报告核对的 Olympia 提交为准；若作者之后公开原始数据，应另建数据来源明确的批次，不覆盖本次固定种子数据。
