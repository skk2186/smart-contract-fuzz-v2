# Phase46：目标状态反馈驱动的多交易序列探索

## 结论

Phase46 对 E3 增加了通用的目标方向反馈、可核验前置状态进展、重复插入已存在的前置动作，以及按目标进展保留多样前缀。它保留原有参数修复和 Phase37 绑定，并按冻结配置在四个案例上运行旧、新两组候选探索。

本轮没有得到算法收益证据。Wallet 两组各回放 12 个候选、各有 10 条完整可执行序列；两组候选指纹完全相同。12 条都观察到属性谓词 getter 变化，但没有目标方向进展，属性始终为真。Olympia 两例的候选部署均被 Python 依赖导入错误阻断。DAllowance 两组各仅回放一次初始序列，未提出候选。没有独立证据表明新方法比旧方法更有效，故停止在候选阶段，未启动 Echidna 或后续实验。

## 失败原因与实现修订

这轮暴露了三类问题，不能简化为“Agent 规划不足”：

1. **Olympia 运行环境未正确对齐。** 两个 PyEVM 任务的每次候选尝试都因 `eth_account._utils.typed_transactions` 导入失败而没有部署。保存的冻结记录没有完整记录实际候选进程的 Python 路径顺序，因此可以确认异常本身，不能从现存记录可靠地还原是哪一条路径优先级导致它。
2. **DAllowance 的前置动作生成没有工作。** 冻结种子故意删去授权步骤，失败交易报告显式 guard 错误 `ALLOWANCE_TOO_LOW`，但旧扩展器未匹配该错误并停止候选生成。状态反馈模块现增加了源码 guard 中错误标识符的精确匹配；单测覆盖该通用行为。此次修订发生在配对结果产生之后，未对 DAllowance 重新回放。
3. **属性表达式传参接错字段。** Phase36 调用反馈函数时将 `property_source`（分析器位置引用）当作属性表达式传入，没有优先传递真实 `property_predicate`。因此 Wallet 的真实比较式没有进入数值距离评价，已观察到的 getter 变化被保守地标为方向未知。现在增加字段选择辅助函数并以单测验证；也没有在本轮候选结果之后重跑 Wallet。

历史起点质量仍是约束：Phase44 已核验 Olympia 目标最短需要 18–64 笔交易；本轮 OLYMPIA-001 起点只有 1 笔，OLYMPIA-076 使用空序列回退。DAllowance 是人为删掉前置授权的诊断输入；Wallet 起点能执行且候选可执行率较高，说明起点质量不能解释所有失败。相较之下，运行时阻断、未生成授权前置动作和属性谓词接线错误分别限制了可执行性、序列补全与评价有效性。

代码已作两项配对实验之后的通用修订：首选真实属性谓词表达式；当执行回滚标识符与静态 guard 中的标识符精确一致时，将其识别为状态前置失败，不误当作一般参数下界。修订后 Phase46 单测 8/8、Phase37 回归单测 7/7 通过。此验证只证明局部逻辑，不改变上述配对结果，也不等同于真实执行有效性验证。修订前后源文件哈希及“不重跑”的机器记录见 `phase46-postrun-code-adjustment.json`。

## 决策与时间

按停止规则，属性反馈没有在真实候选对比中产生可独立核验的目标方向进展；Olympia 的运行失败也使预算对照失效。停止快速 fuzz 和扩大案例，不报告原生反例，也不据此冻结正式评估方案。下一步需先固定 Olympia 的单一依赖环境、验证通用 guard 错误匹配和属性谓词接线可由执行结果观察，再重新冻结小规模配对清单。当前数据不支持“改进优于旧方法”。
