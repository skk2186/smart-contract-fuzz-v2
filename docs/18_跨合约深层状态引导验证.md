# 跨合约深层状态引导验证

## 阶段结论

在 BeeStorage 以外的两个合约中，当前 Agent A/B 流程均生成了可回放的多交易种子，并在 Anvil 确认每笔交易建立了持久状态。目标操作的执行路径有小幅改善，但三次重复的总体覆盖结果并不稳定：Hokusai 平均变化约 −15 条唯一指令，Kink 约 +58 条。第三个预选项目 Request 在一次执行反馈修复后仍未生成有效种子。现有证据支持“方法能在不同合约建立多交易状态”，尚不足以断言它普遍提高整体模糊测试覆盖。

## 样本与对照

样本在运行前按以下标准固定：排除 BeeStorage；每个真实项目选一条至少需要两步状态操作的属性；三条样本分别覆盖 token 增减记账、流动性注入/移除、支付授权/扣款/退款；失败属性保留且仍运行对照。选择依据为现有 Slither 上下文和此前 Agent A 计划，不按本轮结果更换样本。

每条属性使用完整 Agent A + Agent B 流程，最多一轮规划修复及一轮执行反馈修复。Echidna 每次使用相同的 80 测试预算、`seqLen=8`、`shrinkLimit=1`、单线程、不提前停止，并禁用内置 Slither。每属性用随机种子 `20261218`、`20261228`、`20261238` 做三次配对，原生组空语料，V2 组只注入本轮通过 Anvil 验证的唯一种子。全部 6 次有效种子 campaign 均核实加载并回放。没有对种子生成耗时做预算扣除，本轮只比较相同 Echidna 测试数下的覆盖。

## 结果

| 项目 / 属性 | Agent 生成与回放 | 原生唯一指令均值 | V2 唯一指令均值 | V2−原生 | V2 覆盖更高 |
|---|---|---:|---:|---:|---:|
| Hokusai `supply_accounting` | 2 笔；两笔均建立状态，存储槽变化 4、4 | 8,318.7 | 8,304.0 | −14.7 | 2/3 |
| Kink `token1_conserved` | 2 笔；两笔均建立状态，存储槽变化 6、8 | 10,470.7 | 10,528.3 | +57.7 | 2/3 |
| Request `token_conservation` | Agent A 规划 3 笔；退款交易内部回滚，反馈修复后仍失败 | 13,031.0 | 13,031.0 | 0 | 0/3；V2 未注入种子 |

Hokusai 与 Kink 的属性在全部配对运行中均通过，没有发现目标反例，也没有可比较的首次发现时间。按 Agent A 计划中实际操作函数的源码行查看路径：Hokusai 的 `burnInvestorUserA` 平均命中行数为原生 8.3/16、V2 9/16，`mintInvestorUserA` 两组均为 2/3；Kink 的 `singleSidedAdd` 为原生 6/14、V2 7.3/14，`yankLiquidity` 两组均为 6/8。两条 EVM 有效种子确实触达预期操作，但路径行数变化小，未形成稳定的总体覆盖优势。

Request 的第一次 Agent B 请求因 30,000 Token 预算的本地上界预检而未发送。为完成固定样本的完整流程，对该属性单独提高预算上限到 40,000 后重新运行 Agent A/B，并保留原始记录。Agent B 产生三笔参数，执行反馈修复一次；授权和扣款状态成立，退款调用因 `Insufficient refundable amount` 内部回滚，故按既定规则不计 EVM 有效种子。其 V2 空语料对照仍保留，未因失败删除属性。

实际共 8 次 DeepSeek HTTP 请求，API 返回用量合计 41,361 Token；按响应记录的价目估算，费用约为非高峰 0.00624 美元、高峰 0.01247 美元。Request 首次 Agent B 的一次预算预检失败记在调用日志，但不计为 HTTP 请求，也没有 Token 用量。

## 判断

结果排除了“效果只来自 BeeStorage 的 `batchId` 特例”这一种可能：Hokusai 和 Kink 的序列也在不同协议中通过真实执行建立了跨交易状态。然而它们的总体覆盖增益不一致且幅度很小，Request 又暴露出退款额度依赖仍难以由一次反馈修复。现阶段可把研究假设收窄为：执行反馈能提高属性依赖状态的到达率；是否能在更广样本上稳定转化为模糊测试优势，仍需更多预先登记的独立属性和重复。
