# Phase41：统一执行反馈接入与真实合约端到端验证

## 目标与范围

Phase41 将 Phase40 的 Foundry Cheatcode、Anvil RPC 和 Echidna 原生执行结果接入 V2 现有反馈结构，并在 Drips 上运行一次冻结的 Agent A/B、E2、E3 和原生 Echidna 对照。Drips 仍是工程开发与回归样本，不计入独立泛化实验。本轮没有修改 E3 搜索算法、Phase37 参数绑定规则、Drips 业务源码、原生 Harness 或属性语义，也没有新增 Agent。

执行基线为 `06a79c45ebffd1d155c81eb6f7816c09755ff972`。Drips 固定上游 commit 为 `c50d160ead6bf82b1d1071e853dc74da0b23f595`，源码树 SHA-256 为 `fc1b15ff0b5caa5ea2aa624f8d6cf0c51354ca87402891288921b6d2e809f0a0`。使用 solc 0.8.20、Foundry 1.9.0-dev、Echidna 2.3.2。所有源文件及递归 submodule 与冻结版本一致。

通用转换实现在 `func/功能/真实合约统一执行适配器.py`；复用现有 E2、E3、Phase37 扩展器和种子验证的实验驱动为 `func/测试过程/SCFuzzBench公开项目接入/Phase41Drips端到端实验.py`。反馈字段回归测试为同目录下的 `Phase41反馈结构单元测试.py`。原始输入、模型请求输出、机器汇总和执行日志位于 [Phase41 结果目录](../func/测试过程/SCFuzzBench公开项目接入/结果/Phase41-20261123/)。

## 反馈接口

统一转换器将 Foundry 或 Anvil 的部署和调用结果映射为 V2 反馈，包括函数与参数、sender、value、逐笔成功或失败、可取得的回滚数据/原因、时间、配置 getter 的调用前后观察、状态差值、属性检查、目标属性轨迹、失败证据来源及未知字段。转换器被 E2 的现有参数修复和 E3 的现有状态反馈扩展直接调用；Phase37 G2 沿用同一冻结序列和反馈入口启用原有前置约束绑定，不复制搜索逻辑。

Foundry Cheatcode 后端报告测试进程中的调用结果，并原生执行 Harness 内部 `vm.prank`、`hevm.prank` 与时间 cheatcode；这些调用不被标记为独立 mined transaction，也不提供伪造的交易 receipt。Foundry 逐调用状态观察可交给 E2/E3 使用；目标属性仅在 manifest 明确声明并且原生 assertion 确实被调用时绑定。属性内部不可见的中间值保持 `unknown`。Anvil 后端保留独立 RPC 交易 receipt，但仅有序列端点状态时会把中间逐笔 getter 状态标记为不可观察，不按端点差异反推中间交易。

六项反馈字段测试覆盖 Foundry 的 sender/value/状态/失败和属性结果、E3 向量、Anvil 端点观察及缺失逐笔状态的 unknown 标记、manifest assertion 绑定。Phase37 的七项机制测试通过。

## 冻结任务与 Agent A/B

在 Agent 调用之前，仅冻结一项正式任务：`EchidnaSqueezeTests.testSqueezableAmountCantBeUndone(uint8,uint8,uint160,uint32,uint32,int128)`（属性 ID `6e7899beaef22d4a3a87`，源码 `src/echidna/EchidnaSqueezeTests.sol:181-206`）。属性检查 `setStreams` 前后内部计算的 `getSqueezableAmount(sender, receiver)` 是否相等。原始 Harness 没有暴露这两个内部值的 getter，部署时属性状态因此记为 unknown；`splittable` 只能作为部分相关状态观察，不能替代断言操作数。Phase40 的成功 `give → addStreamImmediatelySqueezable → testSqueeze` 序列在输入冻结时明确排除，没有提供给 Agent，也没有作为实验种子。

Agent A 与 B 各进行一次实际规划/实例化，模型均为 `deepseek-flash`，请求和响应以不含授权头的形式保存在 `Drips/agent/API调用.jsonl`。A 输入 624,343 UTF-8 字节，实际使用 194,796 tokens、耗时 3.666 秒；B 实际使用 10,075 tokens、耗时 2.971 秒；合计 204,871 tokens。一次本地 token 预算上界预检在发出 HTTP 请求前拒绝，随后按原冻结上下文进行的 A/B 各一次请求成功；没有重新规划或挑选成功答案。

Agent A 生成一条 `setStreams(...)` 准备操作，Agent B 具体化为两笔调用：`setStreams(0,1,1000,1524785992,1000,1000000)`，随后调用目标断言 `testSqueezableAmountCantBeUndone(1,0,1000,1524785992,1000,1000000)`。两笔均绑定冻结账户、sender 与 value=0。E1 在第一笔因 `Stream receiver amtPerSec too low` 回滚，目标属性函数没有执行。E2 没有从实际观察到的状态证据中得到可应用的数值修复，故不改写 Agent 输出。G1 和 G2 从相同的 Agent 输出指纹开始，各检查 24 个 E3 候选；G1 关闭 Phase37 绑定，G2 开启绑定。两组均无完整可执行序列，均未形成可验证种子。该结果没有显示 Drips 上 G2 相对 G1 的到达优势。

## G0 Echidna 原生对照

在独立干净 corpus、无外部种子、workers=1、Assertion 模式、序列长度上限 8、`testLimit=500` 下，使用预先冻结的随机种子 4041、4042、4043 各运行一次。三组正式预算均完成。目标属性 `testSqueezableAmountCantBeUndone(...)` 在三组中均报告 passing；没有观察到该属性反例。

| 随机种子 | Echidna fuzz 调用计数 | 最终唯一指令数 | 耗时 | 其他 Harness 断言 |
|---:|---:|---:|---:|---|
| 4041 | 501 | 42,005 | 20.030 秒 | `invariantWithdrawAllTokensShouldNotRevert()`、`testReceiveStreamsShouldNotRevert(uint8)` 失败，进程退出码 1 |
| 4042 | 506 | 39,611 | 18.631 秒 | 未观察到其他断言失败，进程退出码 0 |
| 4043 | 501 | 40,402 | 17.419 秒 | 未观察到其他断言失败，进程退出码 0 |

计数按原生 Echidna 输出记录，`tests: x/y` 没有解释为独立交易数。4041 的两个失败属于其他 Harness 断言，不是本轮冻结目标属性；原始日志和机器解析结果保留。E1/G1/G2 未产生有效候选，因此没有运行它们的 seed-only 或 seeded fuzz，也没有将缺失组填为零覆盖。现有 G0 覆盖不能归因为 V2 种子收益。

Echidna 2.3.2 配置提供 `maxTimeDelay`，没有供本轮设置为 Foundry `1524785992` 的初始时间选项；Echidna 的原生时间起点不能据此声称与 Foundry 完全对齐。参见 [Echidna 配置选项](https://secure-contracts.com/program-analysis/echidna/configuration.html)和[端到端测试说明](https://secure-contracts.com/program-analysis/echidna/advanced/end-to-end-testing.html)。因此本阶段报告相同 Harness、目标属性、sender 集和调用预算下的独立结果，不宣称 G0 与 Foundry 的时间语义逐位等价。

## Cheatcode 固定序列与跨后端核验

作为单独的工程 Oracle 回归，使用 Phase40 已验证但未交给 Agent 的三步序列：

1. USER0 调用 `give(0,64,1e18)`；
2. USER0 调用 `addStreamImmediatelySqueezable(0,64,0)`，Harness 内部 `hevm.warp` 推进 1 秒；
3. USER1 调用 `testSqueeze(64,0)`。

新的 Foundry→V2 转换反馈中，三次调用都成功，sender、参数、value、逐步 getter 和属性结果均可见。`receiver_splittable` 从 0 增至 `1e18`，第二步保持，第三步变为 `1e18 + 1`；原生 `testSqueeze` 检查通过。目标状态轨迹取自实际 assertion 结果和配置观察，不推测不可见的内部 operand。Echidna 原生后端对同一固定语料实际回放一条序列；`testSqueeze` 与 `invariantAccountingVsTokenBalance()` 均通过，该固定序列运行中全部 67 个 Harness 属性通过。Foundry 和 Echidna 的结果与相同固定序列及这些属性相一致，但 Echidna 没有输出 Foundry 同粒度的逐笔 getter 和时间轨迹。

这证明统一反馈能够接通 E2/E3 使用的现有数据结构，并证明 Drips 原始 Harness 能在支持 Cheatcode 的 Foundry 后端部署、执行有效状态交易并检查属性。它不证明 Agent 找到目标状态或反例：本轮 Agent 候选没有成功越过第一笔调用。

## Wallet 与 Phase37 回归

- 复测 Phase37 的 B/C/D 原有 9 条代表性 Anvil 确认序列：所有交易成功，冻结目标状态到达且属性为真。七项 Phase37 机制单测通过；Phase37 原开发集结果未被本轮改写。
- Wallet 原已知反例仍通过原 `replay_seed` 执行路径，`deposit(0) → refund(0) → deposit(1) → withdraw(0)` 四笔成功，末笔建立原属性反例。
- 同一 Wallet 反例通过新 `AnvilRpcBackend` 重放，部署和四笔 RPC 交易均成功，属性在序列末为 false。Harness 的 actor 索引保持，sender 映射到本地 Anvil 解锁账户；没有使用 RPC impersonation，也没有用它替代 Drips 内部 prank。Anvil 反馈保留真实 receipt 和序列端点 getter，逐笔 getter 能力明确为 false。

已知的 Phase37 Pigfox 门控退化（跳过 0 项）未删除或写成修复。

## Strata 只读依赖恢复

在 Drips 主线完成后，从可信 npm registry 获取冻结的 `@openzeppelin/contracts@5.3.0` 与 `@openzeppelin/contracts-upgradeable@5.3.0` 归档。两者均与原 `package-lock` 的 SHA-512 SRI 完全匹配；上游 Strata commit、源码树哈希、submodule 和 lockfile 保持原值，未修改业务源码或锁文件。统一准备结果为 `ready`。

Strata 准入在 Forge 离线编译阶段为 `execution_failed`，并非依赖获取失败。原项目还引用了未恢复的 `node_modules/hardhat/console.sol`、`test/recon/targets/PUSDeVaultTargets.sol` 和 `test/recon/targets/YUSDeVaultTargets.sol`。后两个路径不在冻结源码/submodule 中，Hardhat console 也没有在固定归档依赖清单中。没有生成替代 Target、改写源码或继续无限尝试；因此 Strata 没有进入 Harness 部署、交易回放或原生属性验证。

## 结果分级与限制

本轮达到 **B 级：真实端到端接通，但没有有效 Agent 种子**。实际 Agent A/B 输出经统一 Foundry 后端真实回放，得到可追溯的逐笔回滚反馈；E2/E3 的既有接口可读取反馈；G0 完成了三组原生 fuzz。Drips 固定序列通过 Cheatcode 与 Echidna 属性回归，Wallet Anvil 与 Phase37 B/C/D 回归保持通过。

未达到 A 级：E1 首笔回滚、E2 没有证据支持修复、G1/G2 各 24 个候选均未产生完整可执行种子，所以没有 V2 种子验证或 G1/G2 Echidna seeded fuzz 数据。目标属性内部 `getSqueezableAmount` 操作数在未修改 Harness 的条件下不可见；反馈会保持 unknown。Foundry 调用不是独立 mined transactions；Echidna 时间起点没有与 Foundry 精确对齐。G0 4041 的其他两个 Harness 断言失败需作为原始结果保留。Strata 虽恢复两个固定包，仍因另外三个编译输入缺失而未执行。

统一执行及反馈转换已成为可复用的工程基础，可供新项目走项目级 manifest 和正式准入；但目前证据不足以冻结论文级真实项目实验方法并声称 V2 对 Drips 具有状态到达或覆盖收益。Drips 只代表工程回归，不能计入独立泛化。
