# 自主种子质量实验

## 1. 目的

检验不向 Agent 提供人工交易路径、参数模板或预注册前缀时，系统能否依据 Slither 属性上下文自主生成可执行的多交易种子；并比较属性分组、随机批处理、共享前缀和执行反馈对种子质量、覆盖、模型成本及时间的影响。人工已知路径只作为独立上界，不进入 Agent 提示。

本实验是方向性小规模实验，不足以证明对其他协议或属性集合的普遍提升。

## 2. 样本与属性

| 项目 | 样本 | 研究场景 | 使用方式 |
| --- | --- | --- | --- |
| Immutable | `ERC721PsiV2Echidna` 的 6 条原生属性 | ownership、复杂 transfer、approval 清理、group 有界/边界操作、tokenId 溢出 | 分组及全部内部对照 |
| BeeStorage | 属性 `a11cc51249256da90a47` | `bytes32` commit/reveal 两阶段状态依赖、提交者身份 | 自主生成能力检查，不评价分组收益 |
| Drips | 属性 `6e7899beaef22d4a3a87`：`testSqueezableAmountCantBeUndone(...)` | stream/split/receive/squeeze 状态依赖与时间推进 | 自主生成能力检查；已有 8 笔反例只作上界 |

Immutable 的 Slither 关联组大小为 `[2, 4]`：组一为 group 边界与 tokenId 溢出属性；组二为 ownership、transfer、approval 清理和 group 操作属性。随机批处理保持相同组大小，每轮重新抽取分配；三轮分组记录在 JSON 的 `batches` 中。

## 3. 实验配置

- 所有方法使用预先固定的属性集合。每个属性每轮最多占一个候选种子名额；无效、缺失种子保留在分母中。
- Agent 条件上限为每轮 600,000 Token、600 秒；Echidna 2.3.2 每属性 `testLimit=80`、`seqLen=8`。全部方法使用相同上限，实际消耗按模型调用记录，不强行填满预算。
- 每个条件重复 3 轮。Immutable 比较逐属性双 Agent、同规模随机批处理双 Agent、关联分组双 Agent，以及关闭共享前缀和关闭 EVM 执行反馈的消融。关闭执行反馈时仍保留 Agent B 的 ABI/JSON 局部格式修复。
- 原生 Echidna 基线使用同一属性、独立语料目录和相同测试上限；共 24 个属性轮次，全部完成。
- 主方案未提供人工路径、手工参数模板或预注册前缀。上下文由 Slither 结果自动组织。Agent A 生成的 `shared_prefixes` 会进入 Agent B 的种子实例化和前缀回放验证。
- 确定性 Anvil 回放、Echidna 语料加载/回放/后续变异分别记录。只有 Anvil 成功回放的种子计入“EVM 有效种子”；Echidna 原生语料证据不替代 Anvil 有效性。

## 4. Immutable 分组对照结果

每项为三轮结果。覆盖差值是每轮六个独立属性 campaign 的 `unique instructions` 之和减去对应原生 Echidna 基线之和；它不是去重后的全程序覆盖率。状态转换为回放后观察到的成功状态变化；未知变化另行记录。语料列统计成功加载、回放且未发生 worker 崩溃、随后实际进入变异的输入数。

| 方法 | EVM 有效种子 / 18 | Echidna 加载并变异 / 18 | 状态转换中位数（范围） | 覆盖差值中位数（范围） | Token 中位数（范围） | 模型费估算（三轮） | 总时间中位数（范围，秒） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 逐属性双 Agent | 7 | 18 | 7（7–7） | +2,565（+2,381–+3,151） | 142,338（133,460–144,180） | $0.03418 | 81.05（72.11–84.01） |
| 同规模随机批处理 | 4 | 13 | 6（2–7） | +2,309（+865–+2,380） | 131,234（109,514–147,267） | $0.03338 | 73.75（48.26–81.70） |
| 属性关联分组 | 5 | 15 | 5（5–6） | +2,292（+2,277–+2,934） | 138,121（120,735–146,294） | $0.02231 | 65.10（63.23–66.07） |
| 分组、关闭共享前缀 | 6 | 16 | 6（5–7） | +2,303（+2,153–+2,927） | 116,738（99,418–122,428） | $0.02281 | 65.63（54.91–67.96） |
| 分组、关闭 EVM 执行反馈 | 6 | 15 | 6（5–6） | +2,927（+2,588–+2,934） | 105,219（104,550–113,342） | $0.01554 | 56.11（55.99–56.79） |

要点：

1. 属性分组的有效种子为 `5/18`，低于逐属性的 `7/18`；有效状态转换中位数为 5，低于逐属性的 7。覆盖差值也没有高于逐属性基线。当前结果不支持“分组提高种子质量或搜索效果”的结论。
2. 分组 Agent A 每轮均输出并应用 3 个共享前缀；三轮实际复用的前缀交易数分别为 1、2、1，共 4 笔。共享前缀机制确实进入了生成流程，但没有带来有效种子优势。关闭共享前缀后有效种子为 `6/18`，也没有显示前缀提高有效率。
3. 分组上下文的本地 Token 编码中位数由逐属性的 34,236 降至 30,792（约 10.1%）。实际 DeepSeek 调用 Token 中位数仅由 142,338 降至 138,121，且有效种子减少。上下文压缩是可观察到的机制结果，不等价于质量提升。
4. 关联分组总费用低于逐属性条件，但不同方法实际 Token 和缓存命中不同；比较的是同一预算上限下的实测成本，不能解释为同等实际 Token 消耗下的质量差异。
5. 本次 3 轮中 Agent Echidna campaign 没有记录到属性违反。共有 14 轮 Anvil 预验证将 Immutable 的 `echidna_group_operations_sequence()` 标记为交易索引 0 的初始状态违反；但该属性在原生 Echidna 基线 3/3 及 Agent Echidna campaign 中均显示通过。该差异尚未解释，因此不计作种子反例，也不据此认定合约有漏洞。

分组预处理在 Immutable 上重复测量 10 次：属性特征提取中位数 0.012 ms、依赖图构建 0.020 ms、属性合并 0.017 ms。上下文抽取中位数 14.247 ms；去重加本地 Token 编码中位数分别为逐属性 5.430 ms、关联分组 4.467 ms。总时间列已计入分组预处理。

## 5. 多交易样本结果

- **BeeStorage：** 三轮均生成 Anvil 可执行的 commit/reveal 多交易种子，并均被 Echidna 加载、回放和继续变异（3/3）。回放观察器没有公开 getter 可用于确认状态差异，因此状态效果标为 `unknown`，不当作零变化。
- **Drips：** Agent 候选在 Anvil Harness 部署阶段失败（0/3 Anvil 有效），但外部 Echidna 语料均有加载、回放和后续变异证据（3/3）；Agent 条件未发现目标属性违反。这些结果只能证明 Echidna 侧接受并运行该输入，不能证明 Anvil 预验证通过。
- **Drips 人工上界：** 已知 8 笔历史反例从未提供给 Agent。反例种子在 2/3 轮被 Echidna 加载、回放并变异，且目标属性违反；第 3 轮没有加载该种子，但 Echidna 独立模糊测试也违反了目标属性，不能归因于外部种子。由此确认该属性存在可复现反例，同时自主 Agent 尚未复现。

## 6. 纠错记录、成本与限制

- 初次“关闭反馈”配置同时关闭了参数结构修复，属于混杂消融；其质量结果已替换。随后一次纯消融运行完成，但报告在空值序列化时失败，结果未保存；最终又成功重跑三轮，主表采用已保存的校正版。
- 两类作废尝试仍保留成本：混杂配置 229,170 Token、估算 $0.01494066；未保存的校正版首轮 416,522 Token、估算 $0.02954685。作废合计 645,692 Token、约 $0.04448751。成本为 DeepSeek 非高峰价估算，详见[官方价格说明](https://api-docs.deepseek.com/quick_start/pricing/)。
- 主报告所列成功结果共 2,244,516 Token、估算 $0.15241737；连同作废尝试，本轮留档调用合计 2,890,208 Token、估算 $0.19690488。未保存校正过程的首末 API 调用相隔 747 秒；当前报告的精确累计耗时 1,235.461 秒未包含该失败过程，合并后可确认的最低耗时为 1,982.461 秒，失败过程的本地处理时间无法从日志精确恢复。
- Slither 有据的状态转换计数在当前样本全部为 0；表中的状态变化来自 EVM 回放观察器，是另一类证据，不能称为 Slither 证明的转换。
- 样本和重复轮次有限；BeeStorage、Drips 各只有一个属性，不能用于估计分组收益。覆盖数据按属性独立 campaign 求和，可能重复计入同一合约指令。当前证据只适合决定下一步研究方向，不适合声称普遍性能提升。

## 7. 复现命令与产物

在项目根目录执行全量三轮实验：

```powershell
wsl.exe -d Ubuntu-20.04 -- env PYTHONPATH=deepseek:deepseek/实验过程:func/功能 /home/skk/miniconda3/envs/contract-fuzz/bin/python /home/skk/smart-contract-fuzz-v2/deepseek/实验过程/自主种子质量实验.py --repetitions 3
```

只重跑已校正的“关闭 EVM 执行反馈”条件并更新现有报告：

```powershell
wsl.exe -d Ubuntu-20.04 -- env PYTHONPATH=deepseek:deepseek/实验过程:func/功能 /home/skk/miniconda3/envs/contract-fuzz/bin/python /home/skk/smart-contract-fuzz-v2/deepseek/实验过程/自主种子质量实验.py --repair-existing deepseek/结果/自主种子质量实验/自主种子质量实验.json --rerun-method associated_no_feedback
```

`sol/真实项目/DripsSCFuzzBench` 按上游仓库作为 Git 子模块保存；父仓库只记录提交指针，不逐个跟踪子模块内的文件。根目录 `.gitmodules` 已登记其上游地址，当前指针为 `c50d160ead6bf82b1d1071e853dc74da0b23f595`。首次克隆或恢复工作区时运行：

```bash
git submodule update --init --recursive -- 'sol/真实项目/DripsSCFuzzBench'
```

Drips 仓库自己的 Forge Std 和 OpenZeppelin 依赖也是子模块，故命令包含 `--recursive`。本次从 Windows Git 经 WSL UNC 路径检查时，曾遇到嵌套 `.git/modules` 下的权限读取错误；Git 状态和暂存操作改由 WSL 内的仓库路径执行。修改 Drips 源码时，应先在其子仓库提交，再由父仓库更新子模块指针。
