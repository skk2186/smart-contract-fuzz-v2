## 1. 本次修复

| 风险 | 修复与核验证据 |
|---|---|
| 种子 ID 重复 | 使用 `seed-<UUID>`；写入语料前检查 V2 各语料根目录，发现全局同名即拒绝。主实验 40 个 ID 互不相同，且与历史语料 ID 不冲突。全工作区 120 个语料文件对应 60 个 ID；每个 ID 的两份文件是种子包和隔离 Echidna 语料副本，SHA-256 相同，没有不同种子共用 ID。 |
| 语料串用 | 每个方法重复有独立目录，每条属性又有独立 Echidna campaign 目录；拒绝重复运行已有 campaign 根目录。主实验 12 个条件根和 48 个属性 campaign 根均唯一，40 个外部语料均存在。 |
| 失败候选被计作有效种子 | 只有 Anvil 完整回放成功且没有确认的静态写状态无效果，才写入 Echidna 语料。外层交易成功但 Slither 有依据的公开状态 getter 未变化时，标为 `replay_failed`；属性效果无法公开观察时保留为 `unknown`，不擅自判失败。 |
| 内部回滚被 Harness 吞掉 | 回放器将 Slither `effect_evidence` 与交易前后公开 getter 对照。受控故障注入把 capture 金额设为授权额加 1 wei：外层交易收据成功，但 `totalCaptured` 未变化，候选被拒绝；Agent B 在反馈后保留授权前缀、调整参数，回放成功。 |
| 初始属性失败误归因 | Echidna campaign 分别标记初始状态失败、预验证种子已违反、初始后模糊测试发现和未发现失败。四个正式目标属性在 Anvil 与 Echidna 初始状态均通过；48 个正式 campaign 都没有属性失败。 |
| Anvil 时间漂移 | 每次部署前锁定 Echidna 2.3.2 的初始时间戳；固定链 ID、块高、部署者、地址、发送者、余额、Gas 和硬分叉。资格种子连续三次在同一 Anvil 会话中回滚、部署并成功回放，区块号为 4,370,000、部署时间戳为 1,524,785,992。 |
| Agent A 组内一条坏记录影响其他属性 | 先逐条校验并保留有效候选；对没有有效候选的属性子集至多局部重试一次。局部调用计入同一 Token 与墙钟预算，且保留每条属性的错误记录。组规模上限为 4。 |
| 共享前缀仅停留在 JSON | 共享前缀在 Agent A 序列中实际前置；Agent B 对后续属性固定复用首条实例化前缀，逐字段校验函数、参数、发送者、金额与延迟。关联组条件每轮复用 3 次；关闭共享前缀条件为 0 次。 |

### 环境对齐边界

Anvil 与 Echidna 2.3.2 在本实验使用的链 ID、初始块高和时间戳、Harness 地址、部署者、`psender`、发送者池、账户余额、Gas 价格及 Gas 上限上对齐。Anvil 每笔交易以零延迟推进一个区块；Echidna 语料中的交易延迟也均为零。

Echidna 2.3.2 的公开配置没有初始时间戳、初始块高或 EVM 硬分叉的可配置项；时间和块环境使用该版本的确定性默认值，本机探针确认分别为上述时间与块高。Echidna 2.3.2 文档也说明其时间戳固定，并提示与外部 EVM 的时间语义可能不同；因此这里的“对齐”指已核对的交易环境字段，不能外推为任意依赖时间或硬分叉语义的合约完全等价。[配置选项](https://secure-contracts.com/program-analysis/echidna/configuration.html)、[Echidna 时间语义说明](https://secure-contracts.com/program-analysis/echidna/advanced/end-to-end-testing.html)。

## 2. 样本与实验设置

选择 Request 关联组中的四个已有属性：

- `echidna_escrow_not_token_sink`：`63038d1bdccedd2b3b59`
- `echidna_wrapper_not_token_sink`：`66c6ef28ea17e22739c7`
- `echidna_token_conservation`：`c451c42790194538cf50`
- `echidna_fee_receiver_only_gets_fees`：`eebf858bb07972b2891e`

这四个属性的初始值均为 `true`，源码中有共享授权入口、权限/参数边界，并至少需要 `driver_authorizePayment → driver_capturePayment` 两笔交易。预检种子两笔交易都在 Anvil 成功，四条属性初始状态均通过。语义较弱的 `merchant_receives_nonnegative` 在实验前按属性谓词审阅结果排除。

主对照共 2 次重复，每条件统一上限为 400,000 实际 Token、240 秒墙钟、4 个有效外部种子；Echidna 对每属性使用 `test-limit=20`、序列长度 8。每个属性目标分别运行并保留独立 campaign，避免跨属性失败归因混淆。

| 条件 | 方法 |
|---|---|
| 原生 Echidna | 不提供外部种子，直接对四个属性运行 Echidna |
| 逐属性双 Agent | 每个属性单独调用 Agent A，再由 Agent B 实例化 |
| 随机批处理双 Agent | 随机打包属性，使用与其他条件相同的候选、前缀和预算约束 |
| 关联分组双 Agent | 按现有关联组批处理，并执行缺失属性局部恢复 |
| 关联分组、关闭共享前缀 | 同一关联组及恢复策略，不提供/固定跨属性共享前缀 |
| 关联分组、关闭执行反馈 | 同一关联组及共享前缀，Anvil 执行失败后不重试 Agent B |

## 3. 主实验结果

表中为两轮平均值；有效种子数量每轮均相同。Token 统计合并 Agent A、Agent B 和局部恢复调用的模型实际用量。

| 方法 | Token / 条件 | 秒 / 条件 | 有效种子 / 4 | 前缀复用次数 / 轮 |
|---|---:|---:|---:|---:|
| 原生 Echidna | 0 | 4.92 | 不适用（无外部种子） | 0 |
| 逐属性双 Agent | 97,351 | 28.52 | 4 | 0 |
| 随机批处理双 Agent | 101,595 | 29.51 | 4 | 2 |
| 关联分组双 Agent | 105,058 | 28.16 | 4 | 3 |
| 关联分组、关闭共享前缀 | 100,243 | 27.58 | 4 | 0 |
| 关联分组、关闭执行反馈 | 105,055 | 27.37 | 4 | 3 |

**本样本不支持“关联分组降低成本”的假设。** 在达到相同的 4/4 可执行种子数时，关联组比逐属性方法平均多 7,707 Token（约 7.9%），运行时间相近。关联组和无前缀消融的种子数相同，显式共享前缀带来 3 次交易前缀复用，但平均多用约 4,815 Token（约 4.8%），没有改善属性违反发现。当前提示中共享属性上下文与固定前缀的开销抵消了重复推理的预期收益。

局部恢复改变了质量—成本关系：未加入恢复的两轮预实验中，关联组均只有 1/4 个属性得到有效种子，平均 33,696 Token；加入仅对失败属性子集重试后提升到 4/4，但平均成本升至 105,058 Token。随机批处理也由 3/4 恢复到 4/4。预实验完整保留，但不作为修正方法的主结果。

正式 12 个条件总计使用 1,018,603 Token；任何条件均未超过 Token、时间或种子预算。48 个 Echidna campaign 全部有变异运行证据；40 条外部种子均有 Echidna 语料加载和重放日志，之后继续变异。四项目标属性在所有 campaign 中均通过，没有发现属性违反。因此本实验比较的是种子与成本，不提供漏洞发现效率的正向证据，也不表明这些合约不存在缺陷。

关闭执行反馈的正式条件中没有候选触发实际回放失败，所以该消融无法在自然生成样本上评价反馈的增量收益。另行进行的故障注入验证确实触发内部回滚，并成功完成 Agent B 参数修复，消耗 16,169 Token；此成本未计入主实验。

## 4. 失败诊断与处置

1. **Anvil 时间戳不稳定。** 首轮诊断中部署块时间漂移，导致 12 个条件的 Agent 种子全部回放失败。该轮实际用 901,369 Token、耗时 211.626 秒，已保存于 `deepseek/结果/DeepSeek分组可信度时间戳诊断.json`，不纳入正式结果。修复为部署前显式设置 Echidna 默认时间戳，并断言部署块号、时间戳、链 ID 与地址。
2. **默认 Python 版本过旧。** 系统 Python 3.8 在调用属性上下文前因字典合并语法异常中止；没有发出 DeepSeek 请求。之后改用项目 Conda Python 3.11.15，并在实验入口增加版本检查，避免再次跑出部分条件。
3. **中文测试文件未被 unittest discovery 自动发现。** 自动发现显示 0 个测试，因此改为直接执行该回归脚本；最终 7 项测试全部运行并通过。
4. **Agent A 在批量响应中给出不可调用函数。** 规范化器保留同一响应中的有效行并记录坏行；对缺少有效候选的属性子集再请求一次。恢复调用计入主实验 Token 和墙钟预算，未恢复的候选不会写入语料。

早期“未加入局部恢复”的完整预实验保存在 `deepseek/结果/DeepSeek分组可信度修复预实验_无局部恢复.json`，和时间戳失败诊断明确区分。
