- 覆盖率：V2 相比原生 Echidna，有多少条属性提高？平均提高多少？——同测试数预算下 1/10 条提高，唯一正向属性增加 135 条唯一指令；全样本平均差值为 −319.9 条。同端到端 60 秒预算下 2/10 条提高，正向属性平均增加 492 条；全样本平均差值为 −263.4 条（均包含持平和下降属性）。
- 漏洞发现：V2 是否发现更多反例，或者更快发现反例？——没有更多。两组都在 Kink 储备/余额属性上发现同一条目标属性反例；计入种子准备后，原生约 13.76 秒发现，V2 约 17.01 秒。该 Harness 还报告了零交易初始失败，两组均保留。
- 总时间：计入种子生成成本后，V2 是否仍然有优势？——没有观察到优势。同测试数比较中，原生累计约 44.4 秒，V2（含种子准备）约 107.0 秒；同端到端预算中每属性上限均为 60 秒，实测累计约 554.0 秒与 552.0 秒（原生/V2），覆盖率均值仍偏向原生。
- 最终判断：暂无优势。
- 下一步：优先改进 Agent B 的通用提示压缩和 Token 预算分配，让有限修复请求也能在单属性额度内完成，并提高 EVM 有效种子率。

## 实验范围与口径

首轮从缓存 Slither 报告和现存 Harness 中预先固定 10 条属性，覆盖权限控制、状态依赖、数值边界/会计和多交易 commit/reveal，涉及 BeeStorage、Hokusai、Kink 三个真实项目。重复集在筛选前固定为四条属性，每类一条代表；共进行三组配对随机种子。按预登记规则，Drips 的带参数 assertion 在零 API 预检时被 Echidna 2.3.2 拒绝，未改上游源码并由兼容的 BeeStorage 多交易属性替代。完整样本、类别规则和重复名单见[预登记方案](../deepseek/结果/逐属性原生对照实验/扩展属性筛选-20261114/实验方案.json)。

Baseline 使用空且隔离的 Echidna coverage 目录；V2 每条属性独立运行 Agent A、Agent B、Anvil 回放和 Echidna。相同测试预算为 80 个测试；相同端到端预算为每属性 60 秒，V2 从预算中扣除首次种子准备时间。两组使用相同 Echidna 配置和随机种子。只有通过 Anvil 逐交易回放的 EVM 有效种子进入 V2 语料；未产生参数化种子的属性仍运行并计入分母。所有 7 条有效种子都在两种预算的 Echidna 运行中验证为实际加载并回放。未生成或混入 Echidna-only 诊断语料。

## 首轮逐属性结果

覆盖差值定义为 `V2 unique instructions − 原生 unique instructions`；括号内分别是同测试数和同端到端时间预算。Agent A 对 10/10 条生成了交易计划；Agent B 对 8/10 条生成了具体交易参数；其中 7/10 条通过 EVM 回放。

| 项目 / 属性 | 类别 | Agent B 具体化 | EVM 有效 | Δ 80 测试 | Δ 60 秒 |
|---|---|---:|---:|---:|---:|
| BeeStorage `unauthorized_oracle_adjust` | 权限 | 是 | 是 | 0 | +297 |
| Hokusai `only_controller_can_mint` | 权限 | 是 | 是 | −495 | 0 |
| BeeStorage `oracle_price_matches_stamp` | 状态依赖 | 是 | 是 | −691 | −3,529 |
| Hokusai `supplier_distributed_once` | 状态依赖 | 是 | 是 | 0 | 0 |
| BeeStorage `stamp_internal_pot_not_above_balance` | 数值/会计 | 是 | 是 | −1,663 | +687 |
| Hokusai `investor_cap` | 数值边界 | 是 | 否 | 0 | 0 |
| Hokusai `supply_accounting` | 数值会计 | 是 | 是 | +135 | 0 |
| Kink `token1_conserved` | 资产守恒 | 是 | 是 | −485 | −89 |
| Kink `reserves_match_balances` | 状态/数值会计 | 否 | 否 | 0 | 0 |
| BeeStorage `tracked_redist_commit_reveal_consistent` | 多交易/状态依赖 | 否 | 否 | 0 | 0 |

数值上限属性的 Agent B 候选在回放时有一笔包装调用返回成功，但 Slither 关联的 `investorMinted` 状态未变化，因此种子不计为 EVM 有效；随后的一次反馈修复被剩余 Token 上界拦截。Kink 储备/余额与 BeeStorage commit/reveal 属性均有 Agent A 计划，但 Agent B 请求上界分别超过剩余额度，未发出模型请求。失败原因和零费用预检记录均留在原始 JSONL 中。数值边界样本曾使用通用 ABI mutator 清单；清单没有预设路径或参数，Agent A 仍需自行规划。

重复验证的四条预选属性共 12 组配对：同测试数预算下 V2 覆盖更高 1 组、持平 9 组、更低 2 组，平均差值 −258 条指令；同端到端预算下也是 1 组提高、9 组持平、2 组下降，平均差值 −41.3 条。数值属性和多交易属性在三次复用中均未得到 EVM 有效种子，按预登记样本保留。

首轮目标属性反例仅出现在 Kink `reserves_match_balances`。同测试数预算下原生约 13.84 秒、V2 约 17.02 秒；同端到端预算下原生约 13.76 秒、V2 约 17.01 秒。时间均从相应配对运行开始计，V2 包含种子准备成本。该属性在部署初始状态已有零交易失败提示；不能把这次结果解释为种子特有的发现优势。

## 耗时与 API 成本

10 条属性的首次种子准备合计约 66.1 秒，消耗 API 返回的 79,091 个 Token。按 API 返回用量和代码所记录价目估算，费用约为非高峰 0.0144 美元、高峰 0.0288 美元；供应商未返回实际账单金额。Token、费用和失败重试事件按请求保存在各实验的 `API调用.jsonl`。后两轮重复验证复用已支付的种子，不重复计入准备时间，也没有为复跑调用 API；重复报告将复用的历史用量与本轮新增用量分开汇总。
