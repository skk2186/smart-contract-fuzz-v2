# 通用跨交易依赖阶段评估

日期：2026-11-16。范围为现有方法的证据核查和一个留出公开项目的两条原生属性小规模验证。本阶段没有新增 Agent、修改上游合约或针对样本调整生成规则。

## 结论

现有方法能从 Slither 读写关系提出跨交易候选，Agent A 排序，Agent B 具体化，Anvil 用逐笔状态与内部 trace 拦截一部分假成功，再把通过的序列交给 Echidna。但**静态候选尚不能稳定转成可执行的状态建立序列**：初始化状态、创建对象、调用者身份和跨笔参数仍常被误判。已有 Hokusai、Kink 的成功说明方法并非只适用于 BeeStorage；留出 OpenNFTs 的两条属性均失败，说明目前不能宣称通用泛化或相对原生 Echidna 的稳定优势。

本轮固定两条属性：Agent A 计划 2/2，Agent B 产出通过结构校验的具体候选 1/2，Anvil 有效种子 **0/2 条属性、0/1 条具体候选**；生成种子到达计划目标状态路径 **0/2**。两条 V2 campaign 都因无合格种子而使用空语料，故与原生 Echidna 的唯一指令差均为 0，目标反例均为 0。零差异不表示“有效种子无用”，只是本轮未产生可注入种子。

## 现有机制与适用边界

| 环节 | 当前能力 | 未证明或尚不能处理 |
|---|---|---|
| Slither 属性适配器 | 从属性读取状态、候选写入、修饰器、守卫、已解析的高层跨合约调用建立带源码位置的前提闭包；为未知关系保留 `possible_instance_alias`、低层调用不透明等标记。 | 读写同一变量不保证部署后可执行；动态别名、低层调用目标、实际权限身份、构造器已建立状态、数值可满足性不能单靠该图证明。 |
| Agent A | 在候选 ABI 与源码证据中选动作并排序；Hokusai 铸销、Kink 加减流动性曾产出两笔有效序列。 | 可漏掉创建对象的必要前序，或把一次性初始化当成运行期动作；也可能选择只触及相关状态、却不通向目标深层分支的序列。 |
| Agent B | 为固定动作顺序填入参数、发送者、金额；可显式引用前笔唯一事件字段，供回放器绑定实际 ID。 | 仍可把布尔值写成字符串、猜测尚不存在的 token/批次 ID、复用错误身份或构造不满足额度的数值；一轮结构/执行反馈不保证修复。 |
| Anvil 回放 | 逐笔检查外层回滚、内部调用 trace、事件、存储槽和可观察 getter；区分 `state_change`、显式预期拒绝及意外内部失败；只把通过的种子注入 Echidna。 | 存储变化不必然是预期语义；不可观察的内部状态和目标分支仍需额外证据。只凭 receipt 成功会误报低层调用失败。 |
| Echidna 对照 | 可验证语料加载、回放和继续变异，在固定属性、测试数、随机种子和独立目录下比较覆盖及反例。 | 总唯一指令覆盖不等于目标深层路径；同测试数对照未扣除 Slither/模型准备时间，小样本不支持统计泛化。 |

依赖类型上，**状态前置条件**中的简单创建与后续操作已有成功例，但一次性初始化、缺失 mint 和低层调用回滚仍是障碍；**参数传递**中的事件 ID 绑定已有 BeeStorage 反事实修复证据，非事件或多义来源尚未验证；**权限约束**可执行预期拒绝路径，但必须显式声明测试意图，改变所有权还要满足真实 owner 身份；**数值约束**可生成基本金额，Request 可退款额度和 Hokusai 上限等复杂关系仍有失败记录。

## 既有结果的归因

1. [扩展十属性对照](13_扩展属性双Agent种子对照实验.md)：Agent A 计划 10/10、Agent B 具体化 8/10，按当时口径 Anvil 有效 7/10。同 80 测试数，仅 1/10 属性覆盖提高，十属性平均差 −319.9 条唯一指令；60 秒端到端平均差 −263.4。部分失败来自提示体积/Token 预算预检，属于流程成本而非合约不可达。唯一共同发现的 Kink 反例已有零交易初始失败，不是种子优势。
2. [七种子效用核验](14_既有种子效用核验.md)发现外层成功的七条里至少三条含内部回滚，其中两条为权限拒绝、一条为 BeeStorage 错误 `batchId`。因此旧 7/10 是历史口径，不能直接当作“七条完整实现计划效果”。[逐交易回归](15_逐交易效果与依赖绑定回归.md)用 `BatchCreated.batchId` 绑定修复了充值；[三臂对照](16_BeeStorage批次ID修复三臂对照.md)证明新路径能进入，但三次 80 测试的总体覆盖差相对原生为 +2006、+480、−2745，未稳定提高。事件绑定和逐笔效果分类是可复用机制，BeeStorage 的具体事件、状态布局和修复种子不是通用效果估计。
3. [跨项目三属性验证](18_跨合约深层状态引导验证.md)：Hokusai 与 Kink 两笔状态序列确实逐笔建立状态，三次平均总体覆盖差分别约 −15、+58；Request 退款交易因 `Insufficient refundable amount` 内部回滚，一轮反馈后仍无有效种子。Hokusai/Kink 支持状态前置的一定迁移性，但覆盖收益小且不一致；Request 显示跨笔额度关系没有解决。
4. [自主种子质量实验](11_自主种子质量实验.md)中的 Drips 候选在 Anvil 部署失败，而 Echidna 仍曾加载诊断语料；这是语料格式可接受与 EVM 真实有效不同的例子。Immutable 的 `approve` 对不存在 token 回滚，亦是缺少对象创建前置的独立证据。

## 留出样本：OpenNFTs

在执行前把项目及两条未注释的原生 `echidna_*` 属性写入[实验方案](../deepseek/结果/通用依赖泛化验证/实验方案.json)。源码来自 [OpenNFTs 固定提交 `04fbf1e`](https://github.com/Kredeum/OpenNFTs/tree/04fbf1e46ccbb53a07962672fec1463b05768025)，既有仓库快照以前只用于静态分析。保留原生 Harness 及所有失败候选；两属性一轮配对仅是诊断样本。

Slither 0.11.5、solc 0.8.20 完成分析：`echidna_balance` 找到 5 个候选写入动作，`echidna_owner` 找到 2 个。Agent 每属性最多 1 个候选、1 次规划修复、1 次执行反馈修复。Echidna 2.3.2 使用 `testLimit=80`、`seqLen=8`、`shrinkLimit=1`、单线程、不提前停止、禁用内置 Slither；每个属性的原生与 V2 配对使用相同随机种子。原生初始语料为空，V2 仅接纳本轮 Anvil 有效种子。两属性均实际完成 80 测试数上限；日志的总调用数可超过 80，不能把它误写成测试预算。

| 属性 | 生成与失败根因 | 目标状态效果 | 原生 / V2 唯一指令 | 属性反例 |
|---|---|---:|---:|---:|
| `echidna_owner` | Agent A 计划再次 `initialize` 再 `transferOwnership`，但构造器已经初始化，实际 owner 为 `address(42)`。Agent B 两次把 `bool` 参数给成字符串 `"false"`，均在本地结构校验失败，没有进入 Anvil 交易。 | 0 | 5041 / 5041 | 0 / 0 |
| `echidna_balance` | Slither 候选包含 `mint`，Agent A 却只选 `transferFrom`。Agent B 两次回放均因 `Invalid token ID` 回滚；反馈后猜 token ID 0 仍不存在。 | 0 | 5026 / 5026 | 0 / 0 |

两条原生属性均 `passing`，V2 均加载 0 条外部种子。`echidna_balance` 的深层目标至少需要先创建真实 token，再沿正确所有权/接收者传递；本轮生成序列未到达。原生 Echidna 的总 LCOV 不能证明这些动作在同一交易序列中形成该关系，因此**原生深层路径到达率不报数值**。生成种子的目标状态效果到达率按固定属性为 0/2，且一条属性根本没有具体化候选，应与 0/1 的 Anvil 有效具体候选率并列阅读。两条属性均没有发现反例，不能据此认定无漏洞。

本轮 DeepSeek 共 6 次有计量 HTTP 请求、21,955 Token，按现有价目估算非高峰 0.003299586 美元、高峰 0.006599172 美元；不等于实际账单。模型生成耗时没有扣入上述 80 测试数比较。本次由用户明确授权发送这些公开源码及分析上下文至 DeepSeek；调用日志不含密钥。

## 下一阶段优先问题

优先研究**带部署初始状态的可执行前提闭包**：在规划前把构造器已设状态、实际 owner、对象是否存在与候选动作的守卫联合约束；对需要对象 ID 的操作要求先有可验证的创建动作，并以事件或 getter 的实际结果绑定。随后让执行反馈明确区分“参数类型错误”“缺少前序创建”“权限身份不符”“数值关系不成立”，允许针对缺失前置重新规划，而不是只改既定顺序的参数。这个方向同时解释 OpenNFTs、Immutable、Request 和 BeeStorage 的失败，比继续扩大特定合约提示更有研究价值。

完成上述改进后，预登记更多未参与优化的公开项目，逐属性报告：计划率、具体候选率、逐笔效果有效率、目标深层路径到达率、Echidna 语料加载率、配对覆盖与反例；同时做等测试数和含全部准备时间的端到端比较。保留零种子和编译/部署失败项，使用重复随机种子后才判断稳定收益。
