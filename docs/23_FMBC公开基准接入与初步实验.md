## 结论

已将 FMBC 官方仓库固定提交 `01251cc338a6126e8735af87fe3845936150783d` 的完整跟踪文件归档到 `sol/真实项目/FMBC2024/`，并解析全部属性定义、版本、编译约束、依赖和 `ground-truth.csv`。逐文件比对归档副本与固定提交工作树，未发现差异。

数据集定位是 Solidity **形式化验证工具**基准，官方仓库列出的工具是 SolCMC 与 Certora；属性定义多为形式化断言、ghost 状态和转换前后条件，而不是可直接交给 Echidna 的运行时属性。固定提交的主 README 声称 323 项验证任务；本次完整枚举得到 356 条非模板业务合约真值行和 23 条非模板回归真值行，共 379 项。README 数字与固定提交中原始 CSV 矩阵的业务合约行数相差 33；本报告并列保留两者，不按 README 数字删减样本。

全量 379 项中，**没有一项具备可直接运行并与定义等价的动态属性 Oracle**。因此预注册规则冻结出 0 个实验组，未启动 G0/G2。这里的空结果表示“Oracle/接入条件不满足”，不是零发现率、零覆盖率或模糊测试失败。当前应优先补齐通用项目加载和经语义核验的 Oracle 转换能力，再决定 FMBC 的动态测试子集；不应先改 Agent 算法。

## 2. 动态 Oracle 自动检查

脚本逐任务关联自然语言属性、SolCMC 文件、Certora 规则和对应版本源码，并检查版本源码是否包含可被有限交易执行的 `echidna_*` 布尔属性函数。固定提交中没有任何业务或回归版本源码包含该类入口；正式任务 Oracle 分类如下：

| 自动检查结果 | 任务数 | 原因 |
|---|---:|---|
| 有 SolCMC 属性片段，需要语义保持的通用转换 | 204 | 文件使用验证器专用的 `ghost`、`preghost`、`postghost`、`invariant` 等结构；不是可直接部署的 Echidna 属性合约 |
| 仅有 Certora 形式化规则 | 103 | 规则不是有限交易期间可调用的 Oracle |
| 只有自然语言属性定义 | 72 | 没有可执行的原始 Oracle；不能仅凭真值或脚注补造 |
| 可直接运行的可靠动态 Oracle | **0** | 没有 Echidna 风格的运行时属性入口 |

SolCMC 片段不能仅通过把 `assert` 改名或包装成 `echidna_*` 来保证语义等价：ghost 状态、函数前后置条件、隐私状态读取以及回调/重入语义都可能影响判定。为满足“不改原始测试逻辑”和“不强行适配”，本阶段没有改写这些属性，也没有用 `ground-truth.csv` 的标签或脚注生成替代 Oracle。

## 3. V2 接入检查

静态检查现有 V2 的项目上下文、命令入口和 Anvil 回放器：

- [属性上下文模块](../func/功能/属性种子上下文.py) 的 `PROJECTS` 目前只登记 OpenNFTs、Request、Immutable、Hokusai、BeeStorage、Drips、Kink；上下文加载和 Agent CLI 都要求项目名在该静态注册表中。FMBC 任意场景没有通用源码/编译产物入口。
- [种子回放器](../func/功能/种子验证.py) 从注册项目载入编译产物；属性检查依赖无参数、返回 `bool` 且以 `echidna_` 开头的入口。FMBC 的 SolCMC 片段和 Certora 规格无法直接由此评估。
- 因此现有 V2 **不能对本批任意 FMBC 任务端到端运行**。要完成配对实验，至少需要两个通用能力：任意项目的 Slither/编译上下文加载，以及经过语义验证的形式化属性到交易期 Oracle 转换。它们都不应以某个合约名、固定交易序列或手工参数分支实现。
- 缓存环境记录见 [runtime-environment.json](../func/测试过程/FMBC公开基准/结果/Phase23-20261117/runtime-environment.json)：Echidna 2.2.3、Anvil 1.9.0-dev、Slither 0.11.6；默认 solc 0.4.25，solc-select 缓存 0.4.23/0.4.25/0.8.20，另有 0.8.26。数据集含 `^0.8.29` 约束而缓存未见对应编译器版本。这是额外环境差异，并非本次停止运行的首要原因；本阶段未编译合约。

兼容性证据记录在 [v2-compatibility.json](../func/测试过程/FMBC公开基准/结果/Phase23-20261117/v2-compatibility.json)。没有向 DeepSeek 提交任务，未传入漏洞真值、已知反例、脚注或实验结果；Agent API 调用数和调用时间均为 0。

## 4. 样本冻结与最小实验结果

样本规则在任何 G0/G2 运行前写入 [selection-freeze.json](../func/测试过程/FMBC公开基准/结果/Phase23-20261117/selection-freeze.json)：

1. 以 `ground-truth.csv` 中同一场景、同一属性同时有 `sat=1` 和 `sat=0` 的版本作为配对候选；真值只用于离线分组。
2. 要求每个版本有数据集直接提供的 `echidna_*` 运行时属性入口；不从自然语言或真值自动猜造 Oracle。
3. 根据属性文字的关键词归入 temporal、reentrancy、authorization、accounting、call_outcome、generic_state 六类；按类别字典序优先选择不同场景，类别不足时按场景/属性 ID 顺序补足，同一场景最多一组；不根据运行结果重选样本。
4. 固定种子为 `20261117`、`20261118`、`20261119`；端到端单次预算上限 180 秒。配对运行需共用合约属性 Oracle、部署状态、账户集合和时间预算。

冻结结果为 0 个可运行组，因此 G0（ABI 随机交易序列）与 G2（当前 V2）都未启动。逐任务 [G0-G2 状态表](../func/测试过程/FMBC公开基准/结果/Phase23-20261117/G0-G2逐任务状态.csv) 保留了 379 条正式任务，每条均标记为 `not_run_unsupported_oracle`，并给出对应原因。此表的指标栏留空表示未测量；不能解释为 0% 有效交易、0% 目标到达、0% 覆盖或 180 秒超时。没有实际运行日志是因为没有合法样本进入运行阶段，不是用模拟输出替代原始日志。

| Oracle 阻塞类别 | 任务数 | G0 | G2 | 有效交易率 / 目标到达 / 违反 / 覆盖 / 时间 |
|---|---:|---|---|---|
| SolCMC 片段需转换 | 204 | 未运行：无可靠 Oracle | 未运行：属性入口/项目上下文不兼容 | 未测量 |
| Certora 规则 | 103 | 未运行：无交易期 Oracle | 未运行：无交易期 Oracle 及通用入口 | 未测量 |
| 仅自然语言定义 | 72 | 未运行：无可执行 Oracle | 未运行：无可执行 Oracle | 未测量 |

本阶段不是 G0/G2 效果对比，不能据此判断 V2 优于或劣于 ABI 随机生成。没有 API 调用，因此 API 时间为 0；模糊测试运行时间、首次发现时间、有效交易率、目标状态到达率、属性违反数和覆盖率均没有观测值。

## 5. 验收问题与后续建议

1. **完整公开基准有多少任务，多少有可靠动态 Oracle？** 固定提交中 379 条非模板属性 × 版本任务（356 条业务合约、23 条回归）；0 条有可直接运行的可靠动态 Oracle。README 的 323 是另一个未能与固定提交全部 CSV 行数对齐的概述值，已保留该差异。
2. **现有 V2 能否实际运行？** 不能对这些任务端到端运行。主要缺口是项目上下文静态注册、运行属性入口只接受 `echidna_*` bool、FMBC 形式化属性语义无法直接映射到状态转移监控，以及缓存编译器不覆盖全部 pragma。
3. **G0/G2 逐样本结果？** 没有样本通过预注册 Oracle 条件；379 行状态表明确记录为不支持/未运行。不存在可报告的发现率、首次发现时间、覆盖率或运行开销。
4. **V2 是否显示初步优势、是否来自真实目标状态探索？** 无法判断：没有配对运行，也没有目标状态观测。
5. **FMBC 适合作为 V2 正式主实验集吗？** 不适合作为当前阶段的动态模糊测试主集。它面向形式化验证，属性不是普遍可执行的有限轨迹安全检查。可保留为属性来源/后续转换评估集。
6. **下一步做什么？** 优先完善通用执行与 Oracle 框架：支持任意基准项目上下文；为 SolCMC 子集实现可审计、语义保持的通用转换并用正反版本验证；统一 Solidity 编译器和部署配置。只有形成可靠 Oracle 的固定子集后再跑配对实验。若目标是近期评估动态交易序列生成，应另选原生提供可执行状态不变量的模糊测试基准。暂不修改 Agent A/B 算法。
