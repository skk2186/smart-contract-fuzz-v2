# Phase32：独立属性基准建立与跨项目验证

日期：2026-11-20
核验基线：`3eb48e4e7eca917c645305935227f15f28a38d80`

## 结论

本阶段筛查了 13 个任务，在查看 Agent/V2 结果前冻结了 4 个属性任务，来自两个独立上游项目。两个项目都能编译、运行 Echidna smoke，并由 Anvil 部署；四个目标属性的初始状态均为真。

正式流程没有完成到 Echidna 模糊测试。Agent A/B 只产生一条可在 Anvil 完整执行的唯一候选，但其属性相关 getter 未被观察到，未通过冻结的种子入口门。Vault 的两个候选都在第一笔存款交易回滚。Echidna 正式运行又被 Foundry 生成源码兼容问题挡住；把生成源码补齐后，Echidna 2.3.2 仍不能部署该 Foundry Harness。因此，本阶段没有有效的 seed-only 或 500 测试运行，没有 LCOV 比较，也没有独立项目上的有效种子或目标反例。

结论是：Phase32 建成了一个预筛选并冻结的独立任务池，验证了 Boolean、Assertion 和 Foundry 三种 Echidna 属性模式的本地能力，并发现了两个具体集成阻碍；它**没有证明 Phase31 序列扩展能在新项目上产生收益**。目前不应扩大到 20–30 个任务。

- Phase25 的跨交易参数修复结果来自固定案例；同一数据依赖样本在不同 G0/G1/G2 条件下结果并不一致。Phase26 的 48 次固定样本 campaign 把空语料、seed-only、seeded fuzz 和新增 LCOV 分开统计。这些数据没有被本阶段重解释为独立项目效果。
- Phase30A/30B 的 Wallet 是参与开发的样本。Phase30B 的人工 Oracle 只证明目标可达，不计自动发现；其 `tests: 0/1` 是属性状态计数，`fuzzing: 3/1` 是交易进度，不能解释为变异产生了有效目标状态。
- Phase31 的状态反馈扩展、Agent A/B、参数修复规则和预算作为基线冻结。本阶段没有改动 [状态反馈序列扩展.py](../func/功能/状态反馈序列扩展.py) 的搜索或排序规则，也没有新增 Agent。Wallet 回归在 assertion 适配前后都于 10 次扩展候选执行后到达目标，Anvil 总回放均为 11 次，序列相同：`deposit → refund → deposit → withdraw`。耗时分别为 6.400449 秒和 6.699672 秒。该回归只说明通用适配没有破坏已有机制，不属于独立样本证据。

## 属性模式兼容

本地二进制为 Echidna 2.3.2。其 `--help` 列出 `property`、`assertion`、`foundry` 等模式；本阶段用最小合约和工具自测日志确认了以下能力。

| 模式 | 本地证明 | 本阶段判定 |
|---|---|---|
| Boolean Property | Boolean 探针加载并运行；Echidna 官方 flags 样本在 30 次限制内加载 3 个属性，没有反例。 | 支持。 |
| Assertion | Assertion 探针使选定断言失败；普通 `revert` 和不相关的 `AssertionFailed(..)` 控制项通过。 | 支持选定测试函数级别的 Assertion。若同一个函数内有多个断言，Echidna 日志不能可靠指出具体哪一处断言。 |
| Foundry test | 本地 `foundry` 模式找到 `testShrinking` 反例；最小 Harness 需符合 `IS_TEST` 约定。 | 工具模式可运行，但本阶段不把它当作通用属性入口。 |

Vault 的两个属性实际经 `Properties.property_* → CryticAsserts.lte() → assert(false)` 调用。原适配器只看属性函数本体，漏掉库函数内的断言。本阶段在 [属性分析适配器.py](../func/功能/属性分析适配器.py) 加入有界的内部/库函数调用遍历，当前报告能定位到 `CryticAsserts.lte()` 内的 `Panic(0x01)`，并记录调用链。

在 [种子验证.py](../func/功能/种子验证.py) 中增加了所选 Assertion 函数的只读调用检查：选中目标函数返回成功记为通过；目标函数调用返回 `Panic(0x01)` 才记为目标断言失败；普通错误、RPC/部署错误及其他错误走独立错误状态。Anvil trace 现在保留顶层 revert data。此适配尚未在独立样本的真实 Assertion 反例上与 Echidna 完成一致性验证；不能声称其已通过跨引擎反例核验。

最小模式证明及原始日志见 [属性模式探针源码](../sol/单合约测试/Phase32属性模式探针/ModeProbe.sol) 和[模式日志目录](../func/测试过程/SCFuzzBench公开项目接入/结果/Phase32-20261120/属性模式探针/)；Crytic Properties 和 Echidna 官方自测样本分别归档在 `公开工具样本/`，不计为独立合约。

## Echidna 正式对照停止原因

候选 smoke 的结果与正式干净构建结果不同。原始 smoke 日志中 RWA 在 `testLimit=40` 下有 45 次交易调用、8,990 条唯一指令，6 个 Boolean 属性均未报反例；Vault 有 45 次调用、8,651 条唯一指令，但两项目标 assertion 多次告警“never reached”。这些是资格 smoke，不等于四个冻结属性已完成 formal seed/fuzz 对照。

正式运行在正确项目目录内仍然失败。Fresh Foundry 编译产物引用了 5 个 `foundry-pp/DeployHelper…sol` 虚拟源码；本地 CryticCompile 0.3.11 将其当作磁盘文件解析，报 `Unknown file`，Echidna 以 exit code 1 退出。一个隔离诊断把这 5 个源码原样从 build-info 物化后，编译分析继续进行，但 Harness 部署失败，Echidna 报不支持的 `HEVM::deployCode(string,bytes)` cheatcode (`0x29ce9dde`)。这是工具链接入问题，非序列扩展结果。

正确工作目录下共有 30 次空语料/seed-only/500 组调用尝试；30 次均在模糊测试前退出，`fuzzing_transactions=0`、唯一指令数和 LCOV 均不可用。E3、R、S 没有通过入口门的种子，未用其他组的语料回退。因而：

- E0 的 500 次基线没有有效运行；E1/E2 seed-only 也未完成；E3/R/S 没有合格输入。
- 本阶段不能报告目标发现率、seed-only 覆盖、变异新增覆盖、最终覆盖或可比的 fuzz 耗时。
- 30 次 exit-code 1 的工具尝试以及一条低预算部署诊断均只作为失败记录，不算测试结果。

原始调用参数保存在每次运行的 `summary.json`；日志、失败命令和后续诊断分别见 [Tasks-EchidnaCwdFixed](../func/测试过程/SCFuzzBench公开项目接入/结果/Phase32-20261120/Tasks-EchidnaCwdFixed/)、[Diagnostics](../func/测试过程/SCFuzzBench公开项目接入/结果/Phase32-20261120/Diagnostics/)及[机器结论](../func/测试过程/SCFuzzBench公开项目接入/结果/Phase32-20261120/Phase32阶段结论.json)。初始 compile-all 失败、相对路径/构建目录诊断均保留在同一 Phase32 结果目录中，没有覆盖历史记录。为避免重复归档，54 份可由冻结源码重建的 `foundry-build/out` 临时产物已从结果目录移除；对应的源码版本、完整命令、编译记录、Echidna 日志、语料和汇总仍保留。

## 论文证据判断

1. 13 个预检任务均通过当时的编译和 Echidna smoke；其中工具自测和属性示例不计独立协议。正式冻结了两个独立上游项目的四个任务。
2. 完成完整 Agent→Anvil→扩展→Echidna 对照的独立项目数为 **0**。
3. Phase31 方法没有在新项目上生成符合入口门的有效种子；有 1 条可执行候选，但属性相关 getter 未观察到。
4. 新项目自动目标反例数为 **0**。
5. 尚无证据说明这些种子能改善后续 Echidna 探索，因为没有有效的 seed-only 或 fuzz 运行。
6. E3 与 E0/E1/E2、随机 R、静态 S 的覆盖和效率比较均不可用；不能据此声称有优势或退化。
7. 本阶段没有可用于论文主实验的独立正向证据。Assertion 调用链识别、Wallet 回归和工程预检只能归入机制/接入验证。
8. 暂不启动 20–30 个样本扩展。下一步应先解决 Echidna/CryticCompile/Foundry 产物兼容，并使静态属性观察能沿公开合约地址 getter 读取跨合约状态，再对冻结的同一批样本做一次明确的复验计划。Phase32 到此停止，不自动进入下一阶段。
