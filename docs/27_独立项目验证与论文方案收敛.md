# Phase 27：独立项目验证与论文方案收敛

日期：2026-11-17
分支：`main`
基线：`3b7b46e3804e9f97b57c4bdc4a6b56a45718f389`

## 结论

本阶段按用户授权，从指定公开来源检查了 **8 个候选**，冻结了候选池和条件实验方案。严格要求上游 Harness 已有原生 `echidna_*() returns (bool)` 属性后，只有 EulerSwap 通过源码、跨交易状态依赖和当前环境的编译/部署门；其余 7 个没有符合要求的布尔属性。合格项目数 **1，小于预设的 4 个最低门槛**，因此按冻结规则停止，**没有启动 G0、G1、G2 正式模糊测试，没有生成 V2 种子，也没有调用 Agent**。

所以本阶段没有新项目上的 V2 成功/失败次数、参数修复收益、目标到达率、路径覆盖或模糊测试成本数据。不能把候选门检查算作 V2 实验，也不能把 EulerSwap 的 testLimit=0 编译检查当成模糊测试收益。现有证据仍不足以证明 C1/C2 在独立项目上成立，暂不建议进入完整论文写作或投稿准备。

## 研究主线与范围变更

Phase26 已将主线冻结为：

**安全属性分析 → Agent A 交易顺序规划 → Agent B 参数生成 → Anvil 实际执行反馈 → 跨交易参数自动修复 → 有效种子验证 → Echidna 模糊测试。**

本阶段保留这条主线和两个候选贡献，不增加 Agent、属性分组、调度器或新方法模块：

| 候选贡献 | Phase27 后的表述边界 |
|---|---|
| C1：面向安全属性的前置状态及交易序列规划 | Phase25 的四个历史诊断样本支持工程可行性；Phase27 没有足够独立项目，不能宣称已验证跨项目泛化。 |
| C2：执行反馈驱动的跨交易依赖识别与参数修复 | Phase25 的 Request、Immutable、BeeStorage、OpenNFTs 结果仍是固定案例证据；独立项目上的目标状态到达收益尚未测量。 |

Phase26 的零候选冻结只限制在原 V2 注册表和“不新增项目”的范围内。本轮用户明确允许从两个指定公开来源有限引入项目，所以另行建立最多 8 项的候选池。**Phase26 原冻结文件未修改**，其 SHA-256 仍为 `8f1d47c9ae06163dca53855ea63d36477b26e0f2cccff9be4d3cf638612c945d`。本次范围变更、来源版本和门槛保存在[候选池冻结记录](../deepseek/结果/Phase27独立项目验证-20261117/候选筛选/Phase27候选池与方案冻结.json)。

## 唯一通过门槛的候选：EulerSwap

EulerSwap 在固定 commit 中包含三个可被 Echidna 识别的布尔属性：`echidna_CORE_INVARIANTS()`、`echidna_STATE_INVARIANTS()`、`echidna_DEBT_LIMIT_INVARIANTS()`，返回类型均为 `bool`。按冻结的字典序规则，若样本门槛足够，目标属性会是 `echidna_CORE_INVARIANTS()`；本轮没有把它登记为正式目标，也没有据此生成交易序列。

交易依赖可以从原生 Harness 源码直接确认：`Tester` 构造函数部署并初始化 EVK/EulerSwap；`setupEulerSwap` 先给两个 EVault 存入初始资产，再创建交易池并配置授权；后续 `activate`、`swap`、`roundtripSwap` 依赖已创建的池、余额和 reserves。`echidna_CORE_INVARIANTS` 读取 holder 债务、EulerSwap reserves 和曲线状态。相关原始源码路径和 tree hash 已记录在候选 JSON。

唯一环境门检查使用项目原生 `Tester` Harness 和原生配置执行 Echidna 2.3.2 `testLimit=0`。它仅检查编译、Slither、构造部署和初始属性，不运行交易序列。结果为编译成功、Slither 完成、三个属性均 passing、`0 tests / 0 fuzzing / 0 total calls`，总耗时 205.558 秒（编译 175.882 秒、Slither 25.268 秒）。检查过程中通过临时目录的四个直接 Git submodule 及其递归依赖满足编译；没有把源码复制进仓库，也没有开始 fuzz。

第一次相同检查因命令 PATH 未包含已经安装的 `crytic-compile` 而失败；随后加入项目现有 Python 虚拟环境 PATH 后，testLimit=0 检查成功。两次原始记录均保留在[候选筛选证据目录](../deepseek/结果/Phase27独立项目验证-20261117/候选筛选/)。前一次仅是启动环境错误，不作为 EulerSwap 项目失败。

## 冻结的条件实验方案与停止执行

候选池冻结记录同时冻结了条件实验协议，时间早于任何正式 campaign。实际资格门结果只有 1 项，故没有项目达到“至少 4 个独立项目”的启动条件，也没有正式项目属性集可供登记。此时停止比降低布尔属性门、替换候选或改写 Harness 更符合预注册规则。

| 实验臂 | 预注册条件 | 本轮正式运行数 |
|---|---|---:|
| G0 | 原生 Echidna、空外部语料 | 0 |
| G1 | 原始 V2，关闭 Phase25 runtime constraint repair | 0 |
| G2 | 完整 V2，从与 G1 相同的 Agent A/B 原始候选开始，最多一次约束修复 | 0 |

若未来在获准的独立样本池内满足门槛，冻结的配对配置为每臂 `testLimit=5000`、随机种子 `20261125/20261135/20261145`，Echidna 2.3.2、单 worker、coverage 开启、`stopOnFail=false`。每个项目沿用同一上游 Solidity commit、原生 Harness、完整属性集合、原生编译/remapping 和账户/发送者设置；三臂只改变语料及 runtime constraint repair。G1 和 G2 使用一次 Agent A 规划、一次 Agent B 具体化得到的同一份原始序列；G2 最多一次有界修复。无有效种子时保留失败原因、不替换样本，G0 原生对照仍应执行。

测量口径已固定为：

1. 目标交易成功率：目标交易外层执行成功，且内部调用证据没有目标操作回滚。
2. 目标状态到达率：交易后 getter/相关属性状态与调用轨迹共同确认，不用外层 receipt 成功代替。
3. 有效多交易序列比例：完整 Anvil 重放后至少两个状态依赖交易成功，目标操作状态可验证。
4. 覆盖分三段记录：seed-only 回放 LCOV、同预算 fuzz 后新增 LCOV 行、最终 LCOV。唯一指令数、反例数、首次反例时间、端到端时间和 API 使用量分别记录。
5. Echidna 回放通过后仍需查看目标交易是否实际执行；`Sequence replayed` 或属性 passing 不单独作为目标状态到达证据。

本轮 G0/G1/G2 的正式运行均为 0，因此成功率、覆盖差、反例和运行成本都记为 **未测量 / N/A**，不是 0% 或“无反例”。没有真实 Agent 调用，API token 和费用为 0。EulerSwap testLimit=0 门检查的 17028 unique instructions 不属于 fuzz campaign，不纳入覆盖比较。

## 对论文方案的判断

1. **新项目成功/失败数：** 8 个候选中 1 个通过候选资格门、7 个因缺少要求的原生 bool 属性被排除；但 V2 正式实验没有运行，所以新项目上的方法成功数和失败数均为“未测量”，不能写成 0/8。
2. **参数修复是否胜过原始 V2：** Phase27 没有 G1/G2 结果，独立项目上无法比较。Phase25 的四个固定案例不能替代留出项目证据。
3. **模糊测试是否胜过原生 Echidna：** 没有 G0/G1/G2 fuzz campaign，无法判断。
4. **提升与成本：** 没有可报告的 V2 状态到达或覆盖提升。唯一 EulerSwap 门检查耗时 205.558 秒是编译/静态分析开销，不是种子生成或 fuzz 的端到端成本；DeepSeek API 成本为 0。
5. **贡献表述：** C1/C2 保留为候选贡献，但只能描述为由 Phase25 固定案例支持、等待独立验证的机制。C1 不可写成已证明通用规划；C2 不可写成已提升独立项目上的目标到达或覆盖。阶段覆盖拆分是测量方法，不单独宣称新算法贡献。
6. **CCF-C 写作条件：** 尚不具备以独立项目结果支撑核心实证主张的条件。本阶段到达八个候选上限后停止，没有扩大搜索。当前不建议开始完整论文写作或投稿准备；在新的、符合冻结门槛的独立项目集合获得批准前，不追加单项目调参或替代样本。
