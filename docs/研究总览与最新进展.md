# 研究总览与最新进展

更新时间：2026-11-19；仓库：`smart-contract-fuzz-v2`；Phase30A 恢复执行基线：`main / d41890d`

## 一、研究方向

本研究要验证一条面向智能合约安全属性的多交易测试流程：静态分析为目标属性找状态依赖，Agent A 规划交易顺序，Agent B 生成参数，通过 Anvil 的真实执行反馈验证并修复已有候选，最后把有效种子交给模糊测试引擎，观察目标状态和新覆盖。

冻结主线如下：

**安全属性分析 → Agent A 交易序列规划 → Agent B 参数生成 → Anvil 执行反馈与跨交易参数修复 → 有效种子验证 → Echidna / Medusa 模糊测试**

核心研究问题是：在不修改真实合约、Harness 和属性含义的前提下，执行观察驱动的跨交易约束处理能否提高独立项目的有效序列与目标状态到达率，并在相同预算下为模糊测试带来超出种子单独回放的新探索路径。

## 二、当前判断

V2 已形成可运行的研究原型。Phase25 在四个固定诊断案例中验证了跨交易参数修复对 Anvil 目标状态到达的帮助；Phase26 在固定样本中观察到种子辅助 Echidna 的覆盖收益；Phase28 证明 BeeStorage 和 Immutable 的历史种子可以转换并由 Medusa 回放。

这些结果仍不足以证明独立项目泛化。Phase27 没有启动正式对照，Phase29 的五个公开候选中没有一个完成全链路。Phase30A 已在小型公开样本上完成编译、属性分析、Agent 候选、Anvil 执行和 Echidna 语料回放检查；两条候选均可回放，但没有达到冻结目标状态，因此未启动 G0/G1/G2。它仍是工程试点，不构成正式独立评估，也不能证明 V2 优于原生模糊测试。

引擎定位暂定为：**Echidna 继续作为主引擎，Medusa 保留为可选实验路径。** 双引擎兼容性已经有固定案例技术证据，但新项目泛化、两引擎结果可比性和稳定收益尚未建立。

| 候选贡献 | 当前定位 |
|---|---|
| C1：基于事件、getter、Slither 守卫和执行 trace 的跨交易约束解析与修复 | Phase25 固定案例提供正向证据；独立项目泛化未验证，仍是候选贡献。 |
| C2：按阶段区分状态到达、种子回放、后续变异和最终覆盖的测量协议 | Phase26、28、29 证明这种区分对避免错误归因很重要；学术新颖性和独立任务效用仍未验证，不单独宣称算法贡献。 |

## 五、Phase29 最新实验状态

Origin Dollar 的 G0 使用 Echidna、单 worker、序列长度 8、`testLimit=5000`、每次 60 秒，运行三次，随机种子为 `20261129/20261130/20261131`。目标 assertion 均为 passing，断言行 37 命中为 0；最终 unique instructions 分别为 `14448/14079/14907`，选定函数覆盖分别为 `8/9、6/9、6/9` 行。

G1/G2 没有运行，原因包括 V2 状态依赖分析不完整和 Anvil Harness 部署回滚。trace 返回 `execution reverted`，没有解码出具体 revert 数据。Harness 构造函数调用 Foundry 的 `hevm.prank(ADDRESS_VAULT)` 后执行带 `onlyVault` 的 OUSD mint；这与普通 Anvil 环境的差异是目前最有依据的失败解释，但报告仍按源码推断记录。Agent/API 请求也被自动审批拦截，原因是候选提示会包含项目源码和属性上下文；没有向 DeepSeek 发出请求。静态依赖门槛不完整本身也未达到生成候选的条件。

五个候选的详细逐级状态、冻结版本和原始证据见 [Phase29 报告](29_公开基准接入与首次独立验证.md)、[版本清单](../func/测试过程/SCFuzzBench公开项目接入/项目版本冻结.json)及[机器可读逐级结果](../func/测试过程/SCFuzzBench公开项目接入/结果/候选逐级接入状态.json)。

## 六、Phase30A 轻量样本试点状态

样本固定为 SmartBugs Curated 提交 `230e649123477eff332742a59a1c7cc6dc286cab` 中的 `dataset/access_control/wallet_02_refund_nosub.sol`，原始源码 SHA-256 为 `3bf849eea5a234dcf2755aa526f934b3edfa560ee7eac3d70385887e3bc6ff79`。本地上游原文、MIT 文本与完整许可证范围均已归档。样本具有公开已知漏洞，仅属于独立来源工程试点，不属于未知漏洞发现或正式留出集。

属性依据 OWASP 智能合约业务逻辑与经济安全指导，在本轮 V2 结果产生前冻结为：五个隔离测试账户各自的累计 ETH 支出不超过该账户累计存款。原始合约以 solc 0.4.24 编译成功；Harness 编译、原生 Echidna 属性预检和 Slither 属性分析均通过。Slither 找到 deposit/refund/withdraw 三个候选动作，但跨合约状态依赖仍有限。

Agent A/B 生成一条 `deposit(uint8)` → `refund(uint8)` 候选；一次执行反馈把存款值从 1 ETH 降到 0.001 ETH。首轮 Anvil 配置余额仅 `4294967295 wei`，两者都因余额不足失败。按 RPC 错误中性修正为 100 ETH 后，原始与修复序列均通过完整 Anvil 回放，也都被 Echidna 加载并明确回放；两者属性仍为真，公开账本 getter 分别显示 actor 0 的支出与存款相等，因此冻结目标状态未达到。Echidna 探针预算为每种子 1 个测试，但日志为 `tests: 0/1`，只证实语料加载与序列回放，不证实后续变异。

目标状态门槛未满足，G0/G1/G2 没有运行；本轮没有可归因的覆盖收益。初始 WSL 命令入口、余额、Python 依赖选择和 Slither 框架自动识别问题均已解决，当前阻碍是候选没有到达属性目标，且参数修复没有经历跨交易守卫/绑定失败。详情见 [Phase30A 报告](30_轻量级公开合约接入试点.md)、[冻结记录](../func/测试过程/SCFuzzBench公开项目接入/结果/Wallet02Refund/01-input-freeze.json)和[机器结果](../func/测试过程/SCFuzzBench公开项目接入/结果/Wallet02Refund/)。

## 七、方法边界与结论口径

- Agent A/B 的规划和参数生成算法、Phase25 参数修复算法保持冻结。
- 不修改真实项目 Solidity 业务逻辑、原生属性或 Harness 语义；不为了测试通过重写种子。
- 不新增 Agent、属性分组、种子调度器或变异算法。
- 接入成功与方法正向效果分别报告；格式有效、语料加载、交易完整回放、目标状态建立、属性反例和覆盖提升分别记录。
- 每个引擎只与自身同配置的 native 对照比较，不把 Echidna 和 Medusa 的内部覆盖计数直接横向排序。
- Phase25–29 既有结果保留在各自阶段报告和结果目录，不用总览文档替代原始数据。
