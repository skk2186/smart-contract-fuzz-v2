# 研究总览与最新进展

更新时间：2026-11-20；仓库：`smart-contract-fuzz-v2`；Phase32 核验基线：`main / 3eb48e4e7eca917c645305935227f15f28a38d80`

## 一、研究方向

本研究要验证一条面向智能合约安全属性的多交易测试流程：静态分析为目标属性找状态依赖，Agent A 规划交易顺序，Agent B 生成参数，通过 Anvil 的真实执行反馈验证并修复已有候选，最后把有效种子交给模糊测试引擎，观察目标状态和新覆盖。

冻结主线如下：

**安全属性分析 → Agent A 交易序列规划 → Agent B 参数生成 → Anvil 执行反馈与跨交易参数修复 → 有效种子验证 → Echidna / Medusa 模糊测试**

核心研究问题是：在不修改真实合约、Harness 和属性含义的前提下，执行观察驱动的跨交易约束处理能否提高独立项目的有效序列与目标状态到达率，并在相同预算下为模糊测试带来超出种子单独回放的新探索路径。

## 二、当前判断

V2 已形成可运行的研究原型。Phase25 在四个固定诊断案例中验证了跨交易参数修复对 Anvil 目标状态到达的帮助；Phase26 在固定样本中观察到种子辅助 Echidna 的覆盖收益；Phase28 证明 BeeStorage 和 Immutable 的历史种子可以转换并由 Medusa 回放。

这些结果仍不足以证明独立项目泛化。Phase27 没有启动正式对照，Phase29 的五个公开候选中没有一个完成全链路。Phase30A/30B 的 Wallet 样本原先只有人工 Oracle 能到达目标。Phase31 新增一次通用状态反馈序列扩展，在同一 Wallet 上自动生成并经 Anvil、Echidna 重放确认一条目标反例；这是机制验证，不是独立留出评估。Phase32 预检 13 个候选并在查看 Agent 结果前冻结两个公开项目的四项属性任务；两个项目编译、Echidna smoke 和 Anvil 部署均通过，但正式流程未能形成有效属性种子，且 Echidna 2.3.2 与 Foundry 生成源码/部署 cheatcode 存在兼容阻碍。独立项目完整对照数仍为 0，论文主张仍缺跨项目效果证据。

引擎定位暂定为：**Echidna 继续作为主引擎，Medusa 保留为可选实验路径。** 双引擎兼容性已经有固定案例技术证据，但新项目泛化、两引擎结果可比性和稳定收益尚未建立。

| 候选贡献 | 当前定位 |
|---|---|
| C1：基于事件、getter、Slither 守卫和执行 trace 的跨交易约束解析与修复 | Phase25 固定案例提供正向证据；独立项目泛化未验证，仍是候选贡献。 |
| C2：按阶段区分状态到达、种子回放、后续变异和最终覆盖的测量协议 | Phase26、28、29 证明这种区分对避免错误归因很重要；学术新颖性和独立任务效用仍未验证，不单独宣称算法贡献。 |

## 五、Phase29 最新实验状态

Origin Dollar 的 G0 使用 Echidna、单 worker、序列长度 8、`testLimit=5000`、每次 60 秒，运行三次，随机种子为 `20261129/20261130/20261131`。目标 assertion 均为 passing，断言行 37 命中为 0；最终 unique instructions 分别为 `14448/14079/14907`，选定函数覆盖分别为 `8/9、6/9、6/9` 行。

G1/G2 没有运行，原因包括 V2 状态依赖分析不完整和 Anvil Harness 部署回滚。trace 返回 `execution reverted`，没有解码出具体 revert 数据。Harness 构造函数调用 Foundry 的 `hevm.prank(ADDRESS_VAULT)` 后执行带 `onlyVault` 的 OUSD mint；这与普通 Anvil 环境的差异是目前最有依据的失败解释，但报告仍按源码推断记录。Agent/API 请求也被自动审批拦截，原因是候选提示会包含项目源码和属性上下文；没有向 DeepSeek 发出请求。静态依赖门槛不完整本身也未达到生成候选的条件。

五个候选的详细逐级状态、冻结版本和原始证据见 [Phase29 报告](29_公开基准接入与首次独立验证.md)、[版本清单](../func/测试过程/SCFuzzBench公开项目接入/项目版本冻结.json)及[机器可读逐级结果](../func/测试过程/SCFuzzBench公开项目接入/结果/候选逐级接入状态.json)。

## 六、Phase30A 轻量样本试点状态

样本固定为 SmartBugs Curated 提交 `230e649123477eff332742a59a1c7cc6dc286cab` 中的 `dataset/access_control/wallet_02_refund_nosub.sol`，原始源码 SHA-256 为 `3bf849eea5a234dcf2755aa526f934b3edfa560ee7eac3d70385887e3bc6ff79`。本地上游原文、MIT 文本与完整许可证范围均已归档。样本具有公开已知漏洞，仅属于独立来源工程试点，不属于未知漏洞发现或正式留出集。

属性依据 OWASP 智能合约业务逻辑与经济安全指导，在本轮 V2 结果产生前冻结为：五个隔离测试账户各自的累计 ETH 支出不超过该账户累计存款。原始合约以 solc 0.4.24 编译成功；Harness 编译、原生 Echidna 属性预检和 Slither 属性分析均通过。Slither 找到 deposit/refund/withdraw 三个候选动作，但跨合约状态依赖仍有限。

Agent A/B 生成一条 `deposit(uint8)` → `refund(uint8)` 候选；一次执行反馈把存款值从 1 ETH 降到 0.001 ETH。首轮 Anvil 配置余额仅 `4294967295 wei`，两者都因余额不足失败。按 RPC 错误中性修正为 100 ETH 后，原始与修复序列均通过完整 Anvil 回放，也都被 Echidna 加载并明确回放；两者属性仍为真，公开账本 getter 分别显示 actor 0 的支出与存款相等，因此冻结目标状态未达到。Echidna 探针预算为每种子 1 个测试，但日志为 `tests: 0/1`，只证实语料加载与序列回放，不证实后续变异。

目标状态门槛未满足，G0/G1/G2 没有运行；没有可归因的覆盖收益。Phase30A 首轮余额不足、WSL 命令入口、Python 依赖选择和 Slither 框架识别问题均有记录并解决。Phase30B 独立人工 Oracle 证明目标真实可达；自动规划依然没有达到目标。详情见 [Phase30A 报告](30_轻量级公开合约接入试点.md)、[Phase30B 报告](31_目标可达性与多交易规划修复.md)、[冻结记录](../func/测试过程/SCFuzzBench公开项目接入/结果/Wallet02Refund/01-input-freeze.json)和[机器结果](../func/测试过程/SCFuzzBench公开项目接入/结果/Wallet02Refund/)。

## Phase31 当前结果

Phase31 在不改 Wallet 原合约、Harness 或属性的前提下，从冻结的 Phase30B P1 序列出发，自动补入属性相关前置操作和第二个 Harness actor 的存款。四笔调用使 actor 0 的累计提款成为 2 ETH、累计存款为 1 ETH；共享 Wallet 资金池的余额轨迹为 `0 → 1 → 0 → 1 → 0 ETH`。该自动候选区别于 Phase30B 人工 Oracle，且没有作为 Agent 输入或初始语料。

Echidna 2.3.2 对同一 E3 候选在三个固定随机种子的 seed-only 回放中均报告属性失败。`testLimit=500` 组同样先回放并触发反例，只完成 5 次总调用，没有达到 500 个模糊测试预算；E3 seed-only 行覆盖为 41，后续新增行为 0。E0 平均 seed-only 12 行、500 预算后平均 40 行；E1/E2 和正确输入的随机扩展均为 32 行、后续各增加 11 行。E1/E2 是相同候选，参数修复没有提出修改。静态扩展只生成两个候选，分别因共享资金不足回滚、或末笔无持久状态变化而没有合格种子。

首次对照的输入审计发现 A_random/A_static 语料与 E1 完全相同，原因是实验驱动把基线记录选作首个合格候选。这 12 次运行原样保留，不作为消融证据；A_random 用真正的非基线扩展候选补跑三组，A_static 则按预注册门记为无合格种子。Echidna 的 `tests: x/y` 是属性状态计数，`fuzzing: n/500` 也不直接等于独立测试 case 数；本阶段另以 seed-only 与 fuzz 后 LCOV 差集统计覆盖。历史 Phase30A 的 `mutation_evidence=true` 同样是计数误读，已在 Phase30B 原报告中更正。

四个预冻结独立候选 Strata、DODO Cross-Chain DEX、eBTC BSM、Very Liquid Vaults 均因既有属性入口类型或依赖构建问题未进入正式 fuzz；未追加候选。Phase31 结果只支持 Wallet 上的机制可行性，不支持独立泛化。详细数据、原始日志、版本和命令见 [Phase31 报告](32_属性状态反馈与有界序列扩展.md)。

## Phase32 当前结果

Phase32 对 13 个候选完成编译与 Echidna smoke 预检，并在 Agent/V2 结果产生前冻结 Pigfox RWA 与 Recon Vault 两个上游项目的四项属性任务。四项均成功部署到 Anvil，初始目标均为真。Agent A/B 只给出一条可执行 RWA 种子，但它没有改变当前分析器观察到的属性 getter；另一项 RWA 属性未生成合法候选，两个 Vault 候选都在第一笔存款交易回滚。有限扩展执行 88 个候选、97 次 Anvil 回放，没有形成符合入口门的候选。

Boolean Property、Assertion、Foundry 模式均在本地 Echidna 2.3.2 上通过最小探针；Foundry 公开项目正式运行仍受 CryticCompile 对虚拟 `foundry-pp` 源的处理和 `deployCode` cheatcode 支持限制。30 次正式运行调用均在 fuzz 开始前退出。因此 Phase32 没有独立样本反例、覆盖收益或有效种子率证据。当前阶段到此停止，先修复通用 Foundry/Echidna 接入与跨合约 getter 观察问题，再根据明确的复验方案继续；不启动 20–30 项扩大实验。详见 [Phase32 报告](33_独立属性基准与跨项目验证.md)及[机器汇总](../func/测试过程/SCFuzzBench公开项目接入/结果/Phase32-20261120/Phase32阶段结论.json)。
