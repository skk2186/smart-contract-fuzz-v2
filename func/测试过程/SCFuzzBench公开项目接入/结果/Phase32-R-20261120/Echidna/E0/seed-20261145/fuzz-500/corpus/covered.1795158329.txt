  4 |     | /// @title PigfoxProperties — the shared property-harness contract for the estate.
  5 |     | /// @notice Every pigfox contract repo has exactly one `test/Properties.sol`
  6 |     | ///         holding a contract `Properties is PigfoxProperties`. Foundry, Echidna
  7 |     | ///         and Medusa all drive THAT contract, so an invariant can never hold in
  8 |     | ///         one engine and quietly rot in another.
  9 |     | ///
 10 |     | /// @dev    WHY THIS BASE EXISTS AT ALL.
 11 |     | ///         A property harness has a failure mode worse than a failing property:
 12 |     | ///         a property that stops being *registered*. A rename, a stale
 13 |     | ///         `crytic-export/`, artifacts left behind by `forge coverage`, a
 14 |     | ///         `testPrefixes` mismatch — any of these makes a fuzzer walk a smaller
 15 |     | ///         property set and report a green run. It has happened in this estate:
 16 |     | ///         a stale artifact once shrank a five-property set to four and the job
 17 |     | ///         passed. Green on four is not green.
 18 |     | ///
 19 |     | ///         So the count is declared in Solidity, and three independent things
 20 |     | ///         must agree with it before a build passes:
 21 |     | ///
 22 |     | ///           1. `pigfoxPropertyCount()` — this declaration, in the source.
 23 |     | ///           2. The static count of `function echidna_` declarations in
 24 |     | ///              `test/Properties.sol`, checked by
 25 |     | ///              `scripts/property-count.sh --source`.
 26 |     | ///           3. What Echidna and Medusa each actually REGISTERED at runtime,
 27 |     | ///              checked by `scripts/property-count.sh --engine`.
 28 |     | ///
 29 |     | ///         Two of those can be wrong together only if someone edits the source
 30 |     | ///         and the declaration in the same breath, which is a deliberate act with
 31 |     | ///         a diff attached. That is the point.
 32 |     | ///
 33 |     | /// @dev    NO DEPENDENCIES, DELIBERATELY. This file imports nothing — not
 34 |     | ///         forge-std, not OpenZeppelin. It is vendored into consuming repos as a
 35 |     | ///         git submodule under `lib/`, and a base contract that dragged in a
 36 |     | ///         second copy of forge-std would create exactly the duplicate-artifact
 37 |     | ///         confusion the count guard exists to catch.
 38 |     | ///
 39 |     | /// @dev    The pragma is a floating `>=0.8.0` rather than a pin. Consuming repos
 40 |     | ///         pin their own exact `solc` in `foundry.toml`; that pin is the control.
 41 |     | ///         Pinning here too would mean this file blocks a repo from moving
 42 |     | ///         compiler versions independently, for no safety gain.
 43 |     | abstract contract PigfoxProperties {
 44 |     |     /// @notice How many `echidna_*` predicates this harness declares.
 45 |     |     /// @dev    Override with a literal, not a computed expression. The whole
 46 |     |     ///         value of this number is that it is an independent statement of
 47 |     |     ///         intent — deriving it from anything the harness already knows
 48 |     |     ///         would make it agree with a broken harness automatically.
 49 |     |     ///
 50 |     |     ///         `pure` and prefixed `pigfox`, not `echidna_`, so no fuzzer ever
 51 |     |     ///         mistakes the declaration for one of the properties it counts.
 52 |     |     /// @return The number of `echidna_*` predicates in this contract.
 53 |     |     function pigfoxPropertyCount() public pure virtual returns (uint256);
 54 |     | 
 55 |     |     /// @notice A one-line statement of what this harness is proving.
 56 |     |     /// @dev    Read into the CI log by the pipeline so a run says what it
 57 |     |     ///         covered rather than only how many things it covered. Override it;
 58 |     |     ///         the default is deliberately useless so an unoverridden harness
 59 |     |     ///         reads as unfinished rather than as fine.
 60 |     |     /// @return A short human-readable description of the harness.
 61 |     |     function pigfoxHarnessDescription() public pure virtual returns (string memory) {
